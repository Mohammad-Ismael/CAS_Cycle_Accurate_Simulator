# Release v2.8.0.0: Bounded & Unbounded Queues, Built-in Queue Methods, and Dynamic Context Restrictions [CAS-DTINPCIL]

## 1. Overview & Milestone Scope
This release delivers **v2.8.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§7.10 (Queues)**:
  - Declarations of unbounded queues (`data_type queue_name [$];`) and bounded queues (`data_type queue_name [$:bound_val];`).
  - Elements indexed dynamically from 0 to `q.size() - 1`.
- **§7.10.2 (Built-in Queue Methods)**:
  - `q.size()`: Returns current number of elements in the queue as a 32-bit unsigned integer vector (`LogicVal::make_known(32, size)`).
  - `q.push_back(val)`: Appends an element to the tail of the queue. If queue is bounded and maximum size is exceeded, elements beyond the bound are truncated per §7.10.2.2.
  - `q.push_front(val)`: Inserts an element at index 0, shifting existing elements up.
  - `q.pop_front()`: Removes and returns the first element of the queue. If queue is empty, returns a 4-state unknown vector (`'x`) matching the element width and emits a standard warning.
  - `q.pop_back()`: Removes and returns the last element of the queue. If queue is empty, returns a 4-state unknown vector (`'x`) matching the element width and emits a standard warning.
  - `q.delete()`: Empties the queue, resetting its element length to 0. Also supports indexed deletion (`q.delete(index)`).
- **§7.10.3 (Queue Indexing & 4-State Out-of-Bounds Semantics)**:
  - **RHS Read Subscript (`q[index]`)**: Returns element at specified index. If `index < 0`, `index >= q.size()`, or index contains any unknown (`'x`) or high-impedance (`'z`) bits, returns a 4-state unknown vector (`'x`) of the element bit-width (e.g. `8'hxx`).
  - **LHS Write Subscript (`q[index] = val;`)**: Modifies element in-place. If index is out-of-bounds or unknown, the write is ignored with zero side-effects.
- **§7.10.4 & §21.2.3 (Dynamic Type Context Restrictions [CAS-DTINPCIL])**:
  - Continuous assignments to or from queues or queue subscripts are illegal in SystemVerilog. CAS compiles and elaborates with strict validation, emitting `[CAS-DTINPCIL]` (*Dynamic type in non-procedural context*).
  - Passing dynamic queue variables or queue subscripts directly into non-procedural `$monitor` expressions is illegal and produces `[CAS-DTINPCIL]`.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. QueueObject Representation (`CAS/include/common/queue_types.hpp`)
- Queues are represented using `std::deque<LogicVal>` inside `QueueObject`:
  ```cpp
  struct QueueObject {
      std::string name;
      uint32_t elem_width = 32;
      bool is_signed = false;
      int64_t max_bound = -1; // -1 for unbounded [$], >= 0 for bounded [$:N]
      std::deque<LogicVal> elements;

      QueueObject() = default;
      QueueObject(std::string n, uint32_t w = 32, bool s = false, int64_t bound = -1)
          : name(std::move(n)), elem_width(w), is_signed(s), max_bound(bound) {}

      uint32_t size() const { return (uint32_t)elements.size(); }
      void push_back(const LogicVal& val);
      void push_front(const LogicVal& val);
      LogicVal pop_front();
      LogicVal pop_back();
      void delete_all();
      void delete_at(int64_t idx);
      LogicVal get_elem(int64_t idx) const;
      void set_elem(int64_t idx, const LogicVal& val);
  };
  ```

### B. Procedural Queue Method Dispatch
- Method calls in expressions (`popped_val = q.pop_front();`, `q_len = q.size();`) are parsed as `MethodCallNode` and resolved dynamically in `ExprEvaluator::eval()`.
- Method calls as procedural statements (`q.push_back(val);`, `q.delete();`) are parsed as `TaskCallNode` and dispatched synchronously in `Evaluator::execute_statement()` and `StratifiedScheduler::step_process()`.

### C. [CAS-DTINPCIL] Diagnostic Rules
- During elaboration (`Elaborator::elaborate_module`), continuous assignment LHS targets and RHS expressions are recursively inspected. Any reference to a queue identifier, queue subscript `q[i]`, or queue method produces diagnostic:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: queue index select 'q[]' used in continuous assignment per IEEE 1800-2023 section 7.10.4`
- During `$monitor` initialization, argument expressions are verified. Any direct queue reference produces diagnostic:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: queue index select 'q[]' used in $monitor per IEEE 1800-2023 section 7.10.4 & 21.2.3`

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & Parser
- **Lexer (`lexer.hpp`, `lexer.cpp`)**: Added `TOKEN_DOLLAR` (`$`) tokenization for queue dimension specifications.
- **AST Nodes (`ast_module.hpp`, `ast_stmt.hpp`)**: Added `is_queue` and `queue_bound_expr` to `PortNode` and `VarDeclStatementNode`.
- **Parser (`parser_module.cpp`, `parser_stmt.cpp`)**: Parsed `[$]` and `[$:bound]` dimensions for module-level signals, ports, and procedural variables.

### B. Kernel Elaborator & Engine
- Populated `Engine::queue_map` during hierarchical module elaboration.
- Added `is_queue()` and `get_queue()` lookup methods with hierarchical scope resolution.

### C. Expression & Statement Evaluators
- Extended `ExprEvaluator` to evaluate `.size()`, `.pop_front()`, `.pop_back()`, `.delete()`, `.push_back()`, `.push_front()`, and indexed access `q[idx]`.
- Implemented out-of-bounds safety returning `'x` on invalid reads and ignoring out-of-bounds writes.
- Added queue statement interception in `Evaluator` and `StratifiedScheduler` avoiding invalid task lookup traps.
