# Release v3.17.0.0: Interprocess Synchronization & Communication (IEEE Std 1800-2023 §15, Built-in 'semaphore' and 'mailbox', Process Suspension & Wakeup Scheduling, Bounded/Unbounded Mailbox FIFOs, Methods 'get', 'put', 'try_get', 'try_put', 'num', and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.17.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **45.8%** and implementing full IEEE Std 1800-2023 compliance for:
- **§15 (Interprocess Synchronization & Communication)**:
  - **Built-in Semaphore Class (§15.3)**:
    - Declaration syntax: `semaphore sem_handle;` in module and procedural scopes.
    - Instantiation via constructor: `sem_handle = new(int keyCount = 0);`.
    - Blocking key acquisition: `task get(int keyCount = 1);` suspends calling process when insufficient keys are available until satisfied by a deposit.
    - Key return / unblocking: `task put(int keyCount = 1);` increments key count and wakes up waiting threads in strict FIFO order.
    - Non-blocking key acquisition: `function int try_get(int keyCount = 1);` returns `1` and acquires keys if available, or returns `0` without suspending.
  - **Built-in Mailbox Class (§15.4)**:
    - Declaration syntax: `mailbox mbx_handle;` or parameterized `mailbox #(type) mbx_handle;` in module and procedural scopes.
    - Instantiation via constructor: `mbx_handle = new(int bound = 0);` creating unbounded (`bound <= 0`) or bounded (`bound > 0`) message FIFOs.
    - Blocking message placement: `task put(singular message);` places a message into the mailbox, suspending the calling process if a bounded mailbox is full.
    - Blocking message retrieval: `task get(ref singular message);` retrieves and removes the oldest message, suspending the calling process if the mailbox is empty.
    - Blocking message inspection: `task peek(ref singular message);` copies the oldest message without removing it, suspending if empty.
    - Non-blocking methods:
      - `function int try_put(singular message);` returns `1` if space is available (or wakes up a waiting get process), or returns `0` if full.
      - `function int try_get(ref singular message);` returns `1` and retrieves message if available, or returns `0` if empty.
      - `function int try_peek(ref singular message);` returns `1` and copies message if available, or returns `0` if empty.
    - Message inquiry: `function int num();` returns the number of messages currently stored in the mailbox.
  - **Stratified Scheduler Process Suspension & Resumption Scheduling (§4 & §15)**:
    - Integrated synchronization wait flag `is_waiting_sync` in `BoundProcess`.
    - Synchronous thread suspension on blocking calls (`sem.get` with 0 keys, `mbx.get` on empty FIFO, `mbx.put` on full bounded FIFO) without advancing the program counter (`pc`).
    - Immediate synchronous wakeup and active region scheduling in FIFO order upon resource availability.
    - Seamless thread coordination across parallel `fork ... join` hierarchies.
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects continuous assignments driving semaphore or mailbox handles during elaboration with `[CAS-DTINPCIL]`.
    - Rejects bare semaphore or mailbox handles used directly in continuous assignments with `[CAS-DTINPCIL]`.
    - Rejects bare semaphore or mailbox handles used directly in persistent `$monitor` argument lists outside dereferences with `[CAS-DTINPCIL]`.
    - Rejects semaphore or mailbox method calls used directly in `$monitor` argument lists with `[CAS-DTINPCIL]`.
    - Permits standard boolean `null` comparisons (`sem == null`, `sem != null`, `mbx == null`, `mbx != null`).

## 2. Technical Architecture & Implementation Mechanics

### A. Common Synchronization Types (`CAS/include/common/sync_types.hpp`)
- Created `CAS/include/common/sync_types.hpp`:
  - `WaitingThread`: Encapsulates thread PID (`pid`), requested keys (`keys_requested`), destination variable name for mailboxes (`dest_var_name`), and message to put (`val_to_put`).
  - `SemaphoreObject`: Encapsulates `handle_id`, variable `name`, `keys` counter, and FIFO `std::deque<WaitingThread> waiting_threads`.
  - `MailboxObject`: Encapsulates `handle_id`, variable `name`, `bound` limit (0 = unbounded), `std::deque<LogicVal> queue`, and separate `waiting_get_threads` and `waiting_put_threads` FIFOs.

### B. Frontend Lexer & AST Definitions
- **Lexer (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`)**:
  - Added `TokenType::TOKEN_SEMAPHORE` and `TokenType::TOKEN_MAILBOX`.
  - Tokenized `"semaphore"` and `"mailbox"` keywords.
- **AST Nodes (`CAS/include/frontend/ast_module.hpp`, `CAS/include/frontend/ast_stmt.hpp`)**:
  - Added `bool is_semaphore = false;` and `bool is_mailbox = false;` to `PortNode`.
  - Added `bool is_semaphore = false;` and `bool is_mailbox = false;` to `VarDeclStatementNode`.
- **Netlist & Context (`CAS/include/kernel/netlist.hpp`, `CAS/include/kernel/execution_context.hpp`)**:
  - Added `bool is_semaphore = false;` and `bool is_mailbox = false;` to `Net`.
  - Added `bool is_semaphore = false;` and `bool is_mailbox = false;` to `LocalVar`.
  - Initialized handles to default 64-bit zero (`LogicVal(64, 0, 0)`).

### C. Parser Enhancements (`CAS/src/frontend/`)
- **Module Signals & Ports (`CAS/src/frontend/parser_module.cpp`)**:
  - Parsed `semaphore` and `mailbox` signal and port declarations.
  - Handled optional `#(...)` parameter lists on mailbox declarations (e.g. `mailbox #(int) mbx;`).
  - Assigned 64-bit width and VAR net kind to synchronization handles.
- **Procedural Variable Declarations (`CAS/src/frontend/parser_stmt.cpp`)**:
  - Parsed procedural `semaphore` and `mailbox` declarations within tasks, functions, and initial/always blocks.
  - Correctly set `vnode->is_semaphore` and `vnode->is_mailbox`.

### D. Kernel Engine & Elaborator (`CAS/include/engine.hpp`, `CAS/src/kernel/elaborator.cpp`)
- **Engine Synchronization Heap (`CAS/include/engine.hpp`)**:
  - Maintained `semaphore_heap` and `mailbox_heap` maps indexed by unique 64-bit handle IDs.
  - Maintained `semaphore_handle_names` and `mailbox_handle_names` sets.
  - Implemented `allocate_semaphore(int keys)`, `get_semaphore(uint64_t id)`, `allocate_mailbox(int bound)`, `get_mailbox(uint64_t id)`.
  - Implemented handle lookup methods `get_semaphore_handle_id` and `get_mailbox_handle_id` inspecting execution contexts, call frames, and netlists.
- **Elaboration & Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`)**:
  - Bound module-level synchronization nets and populated handle identifier sets.
  - Enforced `[CAS-DTINPCIL]` on continuous assignments targeting or reading semaphore/mailbox signals:
    ```cpp
    throw std::runtime_error("[CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment to semaphore '" + ca->target_name + "' is illegal per IEEE 1800-2023 section 15.3");
    ```
  - Stamped `bp.pid = result.processes.size();` on all elaborated processes.

### E. Evaluator & Scheduler Execution (`CAS/src/kernel/evaluator.cpp`, `scheduler.cpp`)
- **Constructor Execution**:
  - In `execute_statement(BlockingAssignNode*)`: Handled `ClassNewNode` for semaphores (`allocate_semaphore`) and mailboxes (`allocate_mailbox`).
- **Method Execution**:
  - In `execute_statement(TaskCallNode*)`:
    - `sem.get(k)`: Decrements keys if available; otherwise sets `bp.is_waiting_sync = true` and queues thread.
    - `sem.put(k)`: Increments keys and unblocks waiting threads in FIFO order, advancing their PCs and immediately scheduling them via `engine.scheduler.step_process(wpid)`.
    - `mbx.put(msg)`: Pushes message or hands over to waiting get thread; suspends if bounded FIFO is full.
    - `mbx.get(dest)`: Pops message, writes into destination variable via `write_variable`, and unblocks waiting put threads; suspends if empty.
    - `mbx.peek(dest)`: Copies front message; suspends if empty.
- **Expression Evaluator (`CAS/src/kernel/expr_evaluator.cpp`)**:
  - Evaluated `sem.try_get()`, `mbx.num()`, `mbx.try_put()`, `mbx.try_get()`, and `mbx.try_peek()`.
- **Scheduler Suspension Loop**:
  - In `StratifiedScheduler::step_process`:
    - Checks `bp.is_waiting_sync` before and after statement execution.
    - Halts loop without incrementing `bp.pc` when suspended on synchronization primitives.
    - Resumes cleanly at next instruction when unblocked.
