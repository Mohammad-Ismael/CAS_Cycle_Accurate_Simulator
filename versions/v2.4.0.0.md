# Release v2.4.0.0: Named Synchronization Events (event, ->, ->>, @e, wait(e.triggered))

## 1. Overview & Milestone Scope
This release delivers **v2.4.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§15.3 (Event Data Type)**:
  - Keyword and grammar support for `event` declarations: `event <identifier>;` (and comma-separated declarations).
  - Abstract synchronization primitive representation in elaboration netlist with tracking for triggering timestamps and waiting processes.
- **§15.4 (Event Trigger Operators `->` and `->>`)**:
  - Immediate event trigger (`-> e;`): Evaluated in the Active event region, marking the event as triggered at the current simulation timestamp (`last_triggered_time = current_sim_time`) and awakening all waiting processes.
  - Non-blocking event trigger (`->> e;`): Enqueued into the Stratified Scheduler's NBA event queue (`nba_event_queue`) and triggered during the NBA event region of the current time step alongside variable updates.
- **§15.4 & §9.4 (Event Control `@e`)**:
  - Direct synchronization control `@e;` (supporting both parenthesized `@(e)` and non-parenthesized `@e;` forms).
  - Suspends the executing process until the named event is triggered via `->` or `->>`.
- **§15.5 (Persistent Event Triggering `wait(e.triggered)`)**:
  - Persistent state querying: `e.triggered` evaluates to `true` if event `e` has been triggered at any point during the current simulation time step (`last_triggered_time == current_sim_time`).
  - Zero-delay pass-through: If `e` has already been triggered in the current time step, the waiting process avoids race conditions and continues execution in zero simulation time without blocking.
  - Dynamic blocking: If `e` has not yet triggered in the current time step, the process blocks and waits for a subsequent trigger before resuming in the Active region.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Event Data Type & Storage Model (§15.3)
- An event variable is an abstract synchronization object with no data storage or numeric value.
- Netlist structure:
  ```cpp
  struct NamedEvent {
      std::string name;
      uint64_t last_triggered_time = (uint64_t)-1;
      std::vector<size_t> waiting_pids;
  };
  ```
- Events are declared at module scope and elaborated into `Engine::named_events` and indexed via `Engine::named_event_map`.

### B. Trigger Operators & Stratified Scheduling Regions (§15.4)
- **Immediate Trigger (`-> e;`)**:
  - Executes synchronously within the Active region.
  - Updates `event.last_triggered_time = current_sim_time`.
  - Removes all registered process IDs from `waiting_pids`, clears each process's `waiting_event_id = (size_t)-1`, and schedules the unblocked processes into the Stratified Scheduler's Active queue.
- **Non-blocking Trigger (`->> e;`)**:
  - Evaluates immediately in the Active region, queueing a trigger request into `nba_event_queue`.
  - Does not suspend the triggering process.
  - When the scheduler transitions to the NBA region, `commit_nba_updates()` processes all pending NBA event triggers before executing NBA variable commits and scheduling subsequent delta passes.

### C. Persistent Trigger Check & Race Prevention (§15.5)
- Standard Verilog event controls (`@e`) can suffer from race conditions if an event is triggered in the same time step before a process reaches its wait statement.
- `wait(e.triggered)` eliminates this race:
  - If `last_triggered_time == current_sim_time`, the condition is already met; the process advances immediately in zero simulation time.
  - If `last_triggered_time != current_sim_time`, the process records `waiting_event_id` and suspends until an immediate or NBA trigger occurs.

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & AST Grammar
- **Tokens (`lexer.hpp`, `lexer.cpp`)**:
  - Added `TOKEN_EVENT` (`event`).
  - Added `TOKEN_TRIGGER` (`->`) and `TOKEN_NONBLOCKING_TRIGGER` (`->>`).
- **AST Nodes (`ast_stmt.hpp`)**:
  - Added `struct EventTriggerStatementNode : public StatementNode { std::string event_name; bool is_nonblocking = false; };`.
  - Added `struct WaitEventTriggeredStatementNode : public StatementNode { std::string event_name; };`.
  - Extended `ModuleNode` (`ast_module.hpp`) to store parsed `std::vector<std::string> events;`.
- **Parser (`parser_module.cpp`, `parser_stmt.cpp`)**:
  - Parsed module-level `event <id>, <id>;` declarations.
  - Extended `@` event control to parse `@e;` (without parentheses).
  - Parsed `-> e;` and `->> e;` trigger statements.
  - Parsed `wait (e.triggered);` persistent event control statements.

### B. Kernel Elaborator & Bound Process Model (`elaborator.hpp`, `netlist.hpp`, `engine.hpp`)
- Added `struct NamedEvent` to `netlist.hpp`.
- Added `size_t waiting_event_id = (size_t)-1;` to `BoundProcess`.
- Elaborated all module events into hierarchical `named_events` vectors and name-to-index maps.

### C. Stratified Scheduler Engine (`scheduler.hpp`, `scheduler.cpp`)
- Added `struct NBAEventItem { size_t event_id; };` and `std::vector<NBAEventItem> nba_event_queue;`.
- Implemented `trigger_named_event(const std::string& name)` and `trigger_named_event_id(size_t ev_id)` to awaken waiting processes and update trigger timestamps.
- Updated `commit_nba_updates()` to drain and fire all pending `nba_event_queue` triggers.
- Integrated `EventTriggerStatementNode` and `WaitEventTriggeredStatementNode` handling across all three execution contexts:
  * Task activation frames (`call_stack`).
  * Dynamic fork child processes (`dynamic_statements`).
  * Top-level root processes (`proc->body`).
