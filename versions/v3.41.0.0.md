## 1. Overview & Capabilities
Milestone v3.41.0.0 implements native support for IEEE Std 1800-2023 §8.24, enabling out-of-body class method implementations, in-class `extern` method prototypes, scope resolution syntax `class_name::method_name`, out-of-body constructor definitions `function class_name::new(...)`, qualifier inheritance, signature matching, and context diagnostic `[CAS-DTINPCIL]`.

### Key Features Implemented:
1. **In-Class 'extern' Method Prototypes (§8.24)**:
   - Added `TOKEN_EXTERN` keyword to `Lexer`.
   - Updated `FunctionNode` and `TaskNode` with `bool is_extern` and `bool has_body`.
   - Extended `parse_class()` to accept `extern [virtual | static] function/task ...;` declarations.
   - Enforced restriction prohibiting `pure` and `extern` on the same method declaration with diagnostic `[CAS-DTINPCIL]`.

2. **Out-of-Body Method Declarations & Scope Resolution (§8.24)**:
   - Supported scope resolution prefix `class_name::method_name` for out-of-body function, task, and constructor definitions.
   - Supported out-of-body constructor definition syntax: `function class_name::new(...)` without return type specification.
   - In-class qualifiers (`virtual`, `static`) are automatically inherited by the implementation.
   - Prohibited repeating qualifiers (`virtual`, `static`, `extern`) on out-of-body method headers per IEEE 1800-2023 §8.24 with context diagnostic `[CAS-DTINPCIL]`.
   - Supported out-of-body method definitions in package scopes (`package ... endpackage`), file scopes (`$unit`), and module scopes.
   - Supported optional identifier suffixes on `endfunction : class_name::method_name` and `endtask : class_name::method_name`.

3. **Method Signature Verification & Elaboration Checks (§8.24)**:
   - Implemented `bind_out_of_body_function` and `bind_out_of_body_task` linking method bodies to in-class prototypes.
   - Validated that out-of-body methods correspond to declared `extern` methods in the target class (raising `[CAS-DTINPCIL]` if undeclared or not marked `extern`).
   - Prevented duplicate implementations of the same extern method with diagnostic `[CAS-DTINPCIL]`.
   - Verified that argument counts match between prototype and implementation.
   - Verified return type consistency when explicitly specified on out-of-body functions.
   - Added elaboration-time enforcement ensuring all `extern` methods of non-abstract classes are implemented with `[CAS-DTINPCIL]`.

4. **Polymorphic Dispatch & Execution Coordination**:
   - Preserved `current_this` binding during out-of-body method execution, enabling direct access to class properties and `this` / `super`.
   - Seamlessly integrated with virtual method dispatch tables (`vtable`) for overridden extern methods.
