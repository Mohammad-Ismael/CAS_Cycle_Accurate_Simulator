# Release v3.16.0.0: Parameterized Classes & Specializations (IEEE Std 1800-2023 §8.25, Parameter Port Lists '#(...)', Specialization Instantiation 'class_name #(args)', Static Specialization Scopes 'class_name#(args)::member', and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.16.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **44.4%** and implementing full IEEE Std 1800-2023 compliance for:
- **§8.25 (Parameterized Classes)**:
  - **Parameterized Class Declarations (§8.25.1)**:
    - Parameter port list syntax on class declarations:
      ```systemverilog
      class class_identifier #( parameter_declaration { , parameter_declaration } );
          // class body
      endclass
      ```
    - Supports default parameter expressions (e.g., `#(parameter int WIDTH = 16, parameter int OFFSET = 5)`).
    - Class member properties, function argument types, and return values dynamically parameterizable by class parameter expressions.
  - **Class Specialization & Type Disambiguation (§8.25.1)**:
    - Specialization instantiation syntax `class_name #(override_args) handle_name;`.
    - Distinct concrete types generated and managed for distinct parameterizations (e.g. `packet_container#(16,10)` vs `packet_container#(32,100)`).
    - Default parameter fallback when parameter arguments are omitted or partially specified.
    - Canonical specialization name normalization ensuring identical parameter evaluations resolve to unified types across compilation units.
  - **Static Members in Parameterized Classes (§8.25.1)**:
    - Strict adherence to §8.25.1: each specialization of a class with static members maintains its own completely independent storage for static variables and static methods.
    - Static variable modifications in one specialization (e.g. `packet_container#(16,10)`) do not affect other specializations (e.g. `packet_container#(32,100)`).
  - **Specialization Scope Resolution Operator (§8.25)**:
    - Scope resolution syntax on parameterized class specializations:
      ```systemverilog
      class_identifier #( param_expr, ... ) :: member_identifier
      ```
    - Direct invocation of static methods (`packet_container#(16, 10)::get_count()`) and reading/writing of static variables without requiring an object instance handle.
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects specialized class handles appearing directly in continuous assignments (`assign`) during elaboration with `[CAS-DTINPCIL]`.
    - Rejects continuous assignments driving class handle variables with `[CAS-DTINPCIL]`.
    - Rejects static class methods used in continuous assignments with `[CAS-DTINPCIL]`.
    - Rejects static class methods used directly in persistent `$monitor` argument lists outside procedural evaluation contexts with `[CAS-DTINPCIL]`.
    - Rejects bare specialized class handles appearing in `$monitor` argument lists outside field dereferences with `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend AST Nodes & Lexer (`CAS/include/frontend/`)
- **Lexer (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`)**:
  - Added `TokenType::TOKEN_COLON_COLON` to tokenize the scope resolution operator `::`.
- **AST Expressions (`CAS/include/frontend/ast_expr.hpp`)**:
  - `StaticMethodCallNode`: Encapsulates `class_type_name`, `method_name`, argument expressions, and `clone()`.
  - `StaticMemberAccessNode`: Encapsulates `class_type_name`, `member_name`, and `clone()`.
- **AST Statements & Modules (`CAS/include/frontend/ast_module.hpp`, `CAS/include/frontend/ast_stmt.hpp`)**:
  - `ParameterDef`: Equipped with full copy semantics (deep clone of default expressions) to support parameterized class templates.
  - `ClassMemberVar`: Added `is_static`, `msb_expr`, `lsb_expr`, and copy constructor/cloning.
  - `FunctionNode` & `TaskNode`: Added `is_static`, `return_msb_expr`, `return_lsb_expr`, `shared_body` pointer, and `get_body()` accessor.
  - `ClassNode`: Added `parameters` (`std::vector<ParameterDef>`), `is_parameterized`, `param_values` map, `template_class_name`, `has_static_member()`, `get_function()`, and `get_task()`.
  - `TaskCallNode`: Added `class_type_name` parameter to support static task calls across class scopes.

### B. Parser Enhancements (`CAS/src/frontend/`)
- **Class Header & Parameter Parsing (`CAS/src/frontend/parser_module.cpp`)**:
  - In `parse_class()`: Detects `#( ... )` parameter port lists, populates `cls->parameters`, sets `cls->is_parameterized = true`.
  - Recognizes `static` modifier on member variables, functions, and tasks.
  - Preserves bit-range expressions (`msb_expr`, `lsb_expr`) on member variables and function return types.
- **On-Demand Specialization Engine (`CAS/src/frontend/parser_module.cpp`)**:
  - Implemented `parse_class_type_and_specialize()`:
    - Parses specialization argument lists (both positional `#(16, 10)` and named `#(.WIDTH(16), .OFFSET(10))`).
    - Evaluates parameter overrides against default expressions using constant arithmetic folding (`eval_const_expr_with_params`).
    - Generates canonical specialization keys (e.g. `packet_container#(16,10)`).
    - Materializes concrete specialized `ClassNode` instances on demand with evaluated property bit-widths and port widths.
    - Registers specialized classes into `class_map`, `global_classes`, and the current active `ModuleNode`.
- **Procedural Statements & Expressions (`CAS/src/frontend/parser_stmt.cpp`, `CAS/src/frontend/parser_expr.cpp`)**:
  - Procedural variable declarations: Recognizes parameterized class handles `packet_container #(16, 10) pkt16;`.
  - Scope resolution statements: Parses static task/function calls and static variable assignments (`cls::member = expr;`).
  - Primary expressions: Recognizes `class_name#(args)::member` and constructs `StaticMethodCallNode` or `StaticMemberAccessNode`.

### C. Kernel & Runtime Execution Architecture (`CAS/include/engine.hpp`, `CAS/src/kernel/`)
- **Per-Specialization Static Variable Storage (`CAS/include/engine.hpp`)**:
  - Integrated `class_static_mem`:
    ```cpp
    std::unordered_map<std::string, std::unordered_map<std::string, LogicVal>> class_static_mem;
    ```
  - Added `get_class_static_var` and `set_class_static_var` with lazy evaluation of default variable initializers.
  - In `allocate_class_object`: Skips allocating static member variables within instance object property tables.
- **Static Class Method Evaluation (`CAS/src/kernel/expr_evaluator.cpp`)**:
  - Implemented `ExprEvaluator::eval_static_class_method`:
    - Creates isolated subroutine call frame without requiring an object instance (`current_this = nullptr`).
    - Sets active `current_class_def` for resolution of class parameters and static variables.
    - Executes subroutine body statements via `fn->get_body()`.
- **Expression Evaluation & Parameter Resolution (`CAS/src/kernel/expr_evaluator.cpp`)**:
  - In `eval(IdentifierNode*)`:
    - First checks local activation frames.
    - Checks instance properties on `current_this`.
    - Resolves class parameters from `current_this->class_def->param_values` or `current_class_def->param_values`.
    - Resolves static variables from `class_static_mem` via `has_static_member`.
  - In `eval(StaticMethodCallNode*)`: Dispatches to `eval_static_class_method`.
  - In `eval(StaticMemberAccessNode*)`: Retrieves value from `class_static_mem`.
- **Assignments to Static Members (`CAS/src/kernel/evaluator.cpp`)**:
  - In `execute_statement(BlockingAssignNode*)`:
    - Targets containing `::` write directly to `class_static_mem`.
    - Identifier assignments inside class methods targeting static member variables update `class_static_mem`.
    - Member accesses (`obj.alloc_count = ...`) update the static member for `obj->class_type_name`.

### D. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`)
- **Elaboration Context Diagnostics (`elaborator.cpp`)**:
  - Rejects `StaticMethodCallNode` in continuous assignments with `[CAS-DTINPCIL]`.
  - Rejects `StaticMemberAccessNode` in continuous assignments with `[CAS-DTINPCIL]`.
  - Rejects continuous assignment to specialized class handles with `[CAS-DTINPCIL]`.
- **Runtime `$monitor` Diagnostics (`evaluator.cpp`)**:
  - Rejects `StaticMethodCallNode` in `$monitor` arguments with `[CAS-DTINPCIL]`.
  - Rejects specialized class handles in `$monitor` arguments outside property dereferences with `[CAS-DTINPCIL]`.
