# Release v3.32.0.0: Interface Classes ('interface class ... endclass'), Pure Virtual Methods, Multiple Interface Inheritance ('implements'), Interface Extension ('extends'), Polymorphic Interface Dispatch, Cross-Casting ('$cast'), and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §8.26)

## 1. Overview & Milestone Scope
This release delivers **v3.32.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **66.8%** (`[███████████████████████████████████░░░░░░░░░░░] 66.8%`) and implementing full IEEE Std 1800-2023 compliance for:
- **§8.26 (Interface Classes)**:
  - Declarations using `interface class name [extends base1, base2, ...]; ... endclass`.
  - Interface classes define pure abstract contracts that separate method declarations from their implementations.
  - Multiple interface inheritance via extension: `interface class Child extends ParentA, ParentB`.
  - Prohibitions enforced with diagnostic `[CAS-DTINPCIL]`:
    - Direct instantiation via `new` is prohibited.
    - Data member variables and local variables are prohibited.
    - Non-pure method declarations (methods with bodies) are prohibited.
    - Interface classes cannot implement other interface classes (`implements` prohibited on interface class).
- **§8.26.1 (Multiple Interface Implementation on Concrete Classes)**:
  - Concrete classes can extend at most one base class and implement multiple interface classes:
    ```systemverilog
    class eth_packet extends base_trans implements i_checksum, i_inspectable;
    ```
  - Full interface inheritance closure computation during elaboration.
  - Elaboration validation ensuring all pure virtual methods of all implemented interfaces are implemented in the concrete class hierarchy with matching signatures (argument count, names, types, directions, return types).
- **§8.26.2 (Interface Class Handles & Polymorphic Virtual Dispatch)**:
  - Interface class handles (`i_checksum chk_h;`, `i_inspectable insp_h;`).
  - Polymorphic assignment of concrete class instances to interface handles (`chk_h = pkt;`, `insp_h = pkt;`).
  - Polymorphic method invocation on interface handles (`chk_h.is_valid()`, `insp_h.format_header(info)`), dynamically dispatching to the underlying concrete class implementation.
- **§8.26.5 (Cross-Casting Across Interface Hierarchies with $cast)**:
  - Dynamic runtime cross-casting between independent interface class handles that share a common underlying object instance:
    ```systemverilog
    cast_ok = $cast(cross_insp_h, chk_h);
    ```
  - Type-safe subtype verification navigating the complete interface implementation transitive closure.
- **Subroutine and String Extensions**:
  - Full support for `string` datatype in procedural scopes, task/function return types, and subroutine arguments with output write-back.
  - SystemVerilog `$sformatf` built-in string formatting function with integer, decimal, hex, and string format specifiers (`%0d`, `%04h`, `%s`).
  - Subroutine calls to void functions invoked as procedural statements.
- **Context Diagnostics & Semantic Restrictions (`[CAS-DTINPCIL]`)**:
  - Enforced IEEE Std 1800-2023 §8.26:
    - Rejection of data member declarations inside interface classes.
    - Rejection of constructor (`new`) or direct instantiation of interface classes.
    - Rejection of `implements` clauses on interface classes.
    - Rejection of concrete classes extending interface classes.
    - Rejection of unimplemented pure virtual interface methods.
    - Rejection of illegal class assignments to incompatible interface handles.
