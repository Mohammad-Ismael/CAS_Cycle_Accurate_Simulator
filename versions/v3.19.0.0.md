# Release v3.19.0.0: SystemVerilog Configurations (IEEE Std 1800-2023 §33, 'config' / 'endconfig', Top-Level Config Selection, 'design', 'default liblist', Hierarchical Instance Rebinding 'instance path use lib.cell', Global Cell Rebinding 'cell cell_name use lib.cell', and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.19.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **48.6%** and implementing full IEEE Std 1800-2023 compliance for:
- **§33 (SystemVerilog Configurations)**:
  - **Configuration Declarations (§33.3)**:
    - Declaration syntax:
      ```systemverilog
      config config_identifier;
          design [library_name.]top_cell_identifier;
          [ default liblist { library_name } ; ]
          { config_rule_statement }
      endconfig [ : config_identifier ]
      ```
    - Permitted configuration statements: `design`, `default liblist`, `instance ... use ...;`, `cell ... use ...;`.
  - **Top-Level Configuration Selection & Root Resolution (§33.4)**:
    - Support for selecting configurations as simulation root via CLI option `-top <config_identifier>` / `--top <config_identifier>` and `project.json` (`"top_module": "<config_identifier>"`).
    - Extraction of root design module from `design [lib.]top_module;`, scoping and elaborating the targeted module as the hierarchy root.
    - Automatic configuration discovery and application when no explicit `-top` is specified but a `config` block exists whose `design` clause targets the elaborated root module.
  - **Hierarchical Instance Rebinding (§33.4)**:
    - Syntax: `instance <hierarchical_path> use [<lib>.]<cell>;`.
    - Dynamic substitution of designated module implementations for specific hierarchical instances (e.g. `instance tb_v3_19_0_0_regression.dut use work.v3_19_0_0_fast_core;` replacing `v3_19_0_0_default_core` with `v3_19_0_0_fast_core`).
    - Seamless formal-to-actual port reconnecting, internal signal allocation, continuous assign binding, and process instantiation under the rebound cell topology.
  - **Global Cell Rebinding (§33.4)**:
    - Syntax: `cell <cell_identifier> use [<lib>.]<cell>;`.
    - Global substitution of module types throughout the design hierarchy.
  - **Dynamic Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejection of procedural blocks (`initial`, `always`, `always_comb`, etc.), procedural statements, and continuous assignments inside `config ... endconfig` scopes with diagnostic `[CAS-DTINPCIL]`.
    - Rejection of `instance ... use` rules targeting non-existent or invalid hierarchical paths with diagnostic `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Nodes
- **Lexer (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`)**:
  - Added token types:
    - `TokenType::TOKEN_CONFIG` (`"config"`)
    - `TokenType::TOKEN_ENDCONFIG` (`"endconfig"`)
    - `TokenType::TOKEN_DESIGN` (`"design"`)
    - `TokenType::TOKEN_LIBLIST` (`"liblist"`)
    - `TokenType::TOKEN_INSTANCE` (`"instance"`)
    - `TokenType::TOKEN_CELL` (`"cell"`)
    - `TokenType::TOKEN_USE` (`"use"`)
- **AST Nodes (`CAS/include/frontend/ast_module.hpp`)**:
  - Defined `enum class ConfigRuleType { INSTANCE, CELL };`.
  - Defined `struct ConfigRuleNode : public ASTNode` holding rule type, target path / cell identifier, library name, and rebound cell name.
  - Defined `struct ConfigNode : public ASTNode` holding config identifier, file/line metadata, design library, design top module identifier, default liblist, vector of AST rules, instance-to-cell map (`instance_cell_map`), and cell-to-cell rebind map (`cell_rebind_map`).

### B. Parser Implementation (`CAS/include/frontend/parser.hpp`, `CAS/src/frontend/parser_module.cpp`, `CAS/src/frontend/parser.cpp`)
- **Static Configuration Registry**:
  - Added `Parser::global_configs` retaining parsed `ConfigNode` definitions across multi-file compilation units.
- **Pass 1 Multi-File Discovery**:
  - Updated `Parser::parse_packages_only()` to discover and parse `config` blocks alongside `package` blocks during Pass 1 ingestion, ensuring configuration declarations in any file (`design.sv` or `testbench.sv`) are registered before Pass 2 module parsing.
- **Config Parser (`parse_config()`)**:
  - Parses `config identifier;`, `design [lib.]top;`, `default liblist ...;`, `instance hier.path use [lib.]cell;`, and `cell name use [lib.]cell;`.
  - Enforces `[CAS-DTINPCIL]` if procedural blocks, statements, or assignments appear in config scope.

### C. Kernel Elaborator (`CAS/include/kernel/elaborator.hpp`, `CAS/src/kernel/elaborator.cpp`, `CAS/src/main.cpp`)
- **Top Entity Resolution**:
  - When `-top <name>` / `--top <name>` is passed, queries `Parser::global_configs`. If `<name>` matches a config, sets `active_config = config` and resolves top design module to `config->design_top_module`.
  - If no explicit `-top` is given, checks if any configuration targets the auto-detected top module.
- **Elaboration-Time Instance Rebinding**:
  - In `Elaborator::elaborate_module()`, when iterating over module instantiations, checks if `child_scope` matches `active_instance_cell_map` or `inst->module_type` matches `active_cell_rebind_map`.
  - If matched, substitutes `inst->module_type` with the rebound cell definition, connecting ports and instantiating processes from the substitute module.
- **Non-Existent Path Diagnostic**:
  - Accumulates all valid instantiated hierarchical scopes in `valid_instance_paths`.
  - Post-elaboration check verifies every instance rule in `active_config->instance_cell_map` targets a valid instantiated scope; throws `error: [CAS-DTINPCIL]` if an invalid path is targeted.
