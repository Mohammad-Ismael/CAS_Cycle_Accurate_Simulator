# Release v3.18.0.0: SystemVerilog Packages (IEEE Std 1800-2023 §26, 'package' / 'endpackage', Wildcard Import 'import pkg::*;', Explicit Import 'import pkg::item;', Package Scope Resolution 'pkg::symbol', Shared Types, Packed Structs, Enums, Package Functions, and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.18.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **47.2%** and implementing full IEEE Std 1800-2023 compliance for:
- **§26 (SystemVerilog Packages)**:
  - **Package Declarations (§26.2)**:
    - Declaration syntax: `package package_identifier; ... endpackage [ : package_identifier ]`.
    - Package items permitted: parameters, localparams, typedefs (enums, packed structs), automatic/static functions, tasks, classes, DPI-C imports and exports, and package imports.
    - Package parameters behave as constants (cannot be overridden by instantiation `#(...)`).
  - **Import Declarations (§26.3)**:
    - Wildcard import syntax: `import package_identifier::*;` making candidate package items available for unqualified resolution.
    - Explicit import syntax: `import package_identifier::item_name;` importing specific symbols into the current scope.
    - Supported at compilation-unit level and inside module/interface/package headers and bodies.
  - **Explicit Scope Resolution Operator `pkg::symbol` (§26.3)**:
    - Direct access to package symbols without requiring explicit or wildcard import.
    - Supported in type references (e.g. `bus_proto_pkg::bus_hdr_s pkt_hdr;`), constant expressions/parameters (e.g. `bus_proto_pkg::ADDR_MASK`), enum literals (e.g. `bus_proto_pkg::CMD_READ`), static method calls (e.g. `bus_proto_pkg::compute_tag(...)`), and casts (e.g. `bus_proto_pkg::bus_cmd_e'(expr)`).
  - **Shared Types, Packed Structs, and Enums across Compilation Units**:
    - Automatic propagation of struct layout definitions, bit offsets, member names, and enum constant value maps from package definitions across multi-file compilation units.
    - Seamless field extraction and field assignment (e.g. `pkt_hdr.cmd`, `pkt_hdr.reserved`, `pkt_hdr.addr`).
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Disallows module or interface declarations inside package scope, throwing diagnostic `[CAS-DTINPCIL]`.
    - Disallows module or interface instantiations inside package scope, throwing diagnostic `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Definitions
- **Lexer (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`)**:
  - Added `TokenType::TOKEN_PACKAGE` and `TokenType::TOKEN_ENDPACKAGE`.
  - Tokenized `"package"` and `"endpackage"` keywords.
- **AST Nodes (`CAS/include/frontend/ast_module.hpp`)**:
  - Defined `struct PackageNode : public ASTNode` containing:
    - `std::string name;`
    - `std::vector<ParameterDef> parameters;`
    - `std::unordered_map<std::string, uint64_t> param_constants;`
    - `std::vector<std::unique_ptr<TypedefNode>> typedefs;`
    - `std::unordered_map<std::string, std::shared_ptr<EnumTypeNode>> enum_typedefs;`
    - `std::unordered_map<std::string, std::shared_ptr<StructTypeNode>> struct_typedefs;`
    - `std::unordered_map<std::string, LogicVal> enum_constant_map;`
    - `std::vector<std::unique_ptr<FunctionNode>> functions;`
    - `std::unordered_map<std::string, FunctionNode*> function_map;`
    - `std::vector<std::unique_ptr<TaskNode>> tasks;`
    - `std::unordered_map<std::string, TaskNode*> task_map;`
    - `std::vector<std::shared_ptr<ClassNode>> classes;`
    - `std::unordered_map<std::string, ClassNode*> class_map;`
    - `std::vector<std::shared_ptr<DpiImportNode>> dpi_imports;`
    - `std::unordered_map<std::string, DpiImportNode*> dpi_import_map;`
    - `std::vector<std::shared_ptr<DpiExportNode>> dpi_exports;`
    - `std::unordered_map<std::string, DpiExportNode*> dpi_export_map;`
    - `std::vector<std::string> wildcard_imports;`
    - `std::unordered_map<std::string, std::pair<std::string, std::string>> explicit_imports;`
  - Added `std::vector<std::string> wildcard_imports;` and `std::unordered_map<std::string, std::pair<std::string, std::string>> explicit_imports;` to `ModuleNode`.

### B. Parser Enhancements (`CAS/include/frontend/parser.hpp`, `CAS/src/frontend/`)
- **Package Parsing (`CAS/src/frontend/parser_module.cpp`)**:
  - Implemented `parse_package()` parsing parameters, typedefs, functions, tasks, classes, and DPI-C imports/exports inside package bodies.
  - Implemented diagnostic `[CAS-DTINPCIL]` throwing on illegal module/interface declarations or instantiations in package scope.
- **Package Imports**:
  - Differentiated DPI-C imports (`import "DPI-C" ...`) from package imports (`import pkg::*;` and `import pkg::item;`).
  - Handled compilation-unit level and module-level import directives.
- **Typedef & Package Scope Resolution**:
  - Enhanced `is_typedef(name)`, `get_enum_typedef(name)`, and `get_struct_typedef(name)` in `Parser` to resolve across local typedefs, explicitly imported items, wildcard-imported packages, and explicit scope resolutions (`pkg::type`).
  - Supported package-qualified signal declarations (e.g. `bus_proto_pkg::bus_hdr_s pkt_hdr;`) in both module scope (`parser_module.cpp`) and procedural block scope (`parser_stmt.cpp`).
  - Supported typedef and package-qualified types for function and task return types and formal input arguments (`parser_function.cpp`, `parser_task.cpp`).
  - Supported package-qualified type casting `pkg::type'(expr)` in `parser_expr.cpp`.

### C. Kernel Elaborator & Engine (`CAS/src/kernel/elaborator.cpp`, `CAS/include/engine.hpp`)
- **Package Elaboration**:
  - Registered all package parameters, enums, packed structs, functions, tasks, classes, and DPI imports/exports into `ElaborationResult`.
  - Bound wildcard and explicit package imports into each importing module's scope during module elaboration.
- **Constant Expression Evaluation**:
  - Added support for `StaticMemberAccessNode` in `Elaborator::eval_const_expr` resolving `pkg::PARAM` and `pkg::ENUM_MEMBER`.

### D. Expression Evaluator (`CAS/src/kernel/expr_evaluator.cpp`)
- Evaluated `StaticMemberAccessNode` for package parameters, enum constants, and package variables.
- Evaluated `StaticMethodCallNode` for package functions and methods.

## 4. CAS Studio GUI & Multi-File Package Discovery Ingestion
- **Two-Pass File Ingestion & Ordering Independence**:
  - Implemented `Parser::parse_packages_only()` in `main.cpp` as Pass 1 across all source files, registering all package AST definitions prior to Pass 2 module parsing and elaboration.
  - Guarantees seamless resolution of package-scoped types (`pkg::type`) and wildcard/explicit imports regardless of file CLI argument ordering (e.g. `testbench.sv` before `design.sv`).
- **Disambiguation of Scoped Variable Declarations vs Instantiations**:
  - In `CAS/src/frontend/parser_module.cpp` and `parser_stmt.cpp`, tokens matching `TOKEN_IDENTIFIER` followed by `::` are directly consumed as package-qualified type specifiers rather than falling through to module instantiation logic, eliminating spurious `"Expected instance identifier (found: '::')"` errors.
- **CAS Studio HTTP Simulation Verification**:
  - Verified `POST /api/simulate` on `v3_18_0_0_packages` responds with HTTP 200 OK, zero parse errors, and 100% pass parity.
