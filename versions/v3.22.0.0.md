# Release v3.22.0.0: SystemVerilog Assertions (SVA) Sequence Match Subroutine Calls '(seq_expr, subroutine_call(...))', Argument Passing with Sequence Local Variables and Sampled Preponed Values, Subroutine Side-Effect Execution in Reactive Region, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §16.11)

## 1. Overview & Milestone Scope
This release delivers **v3.22.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **52.8%** and implementing full IEEE Std 1800-2023 compliance for:
- **§16.11 (SystemVerilog Assertions: Sequence Match Subroutine Calls)**:
  - **Sequence Match Subroutine Syntax**:
    - Calls permitted within sequence item match lists:
      ```systemverilog
      ( sequence_expr , subroutine_call_or_assignment { , subroutine_call_or_assignment } )
      ```
    - Support for tasks, void functions, value-returning functions (with discarded return values), and system tasks (`$display`, etc.).
  - **Argument Passing with Sequence Local Variables & Sampled Preponed Values**:
    - Arguments passed to match subroutines are evaluated at the exact time and context of the sequence match.
    - Argument expressions resolve against sequence local variables (`in_val`) and sampled Preponed signal values (`rx_data`).
  - **Subroutine Side-Effect Execution in the Reactive Region**:
    - Evaluated arguments and subroutine descriptors are enqueued in `pending_subroutines` upon sequence expression match.
    - Subroutine execution and side-effects (e.g. global counters, logged packet headers) execute in the Reactive region of the current time slot.
    - Updates are committed before the Postponed region, ensuring deterministic visibility in `$monitor`.
  - **Blocking Timing Control Restriction & Dynamic Context Diagnostic (`[CAS-DTINPCIL]`)**:
    - Per IEEE 1800-2023 §16.11, subroutines invoked on sequence match shall not contain blocking timing controls (`#`, `@`, `wait`, `wait fork`, `forever`).
    - Immediate rejection with diagnostic `[CAS-DTINPCIL]` if any blocking construct is encountered inside a sequence match subroutine.
    - Rejection of sequence match items in non-procedural contexts such as continuous assignments (`assign`) and `$monitor`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend AST Nodes (`CAS/include/frontend/ast_expr.hpp`, `CAS/include/common/sva_types.hpp`)
- Generalized match actions in `SequenceMatchAction`:
  ```cpp
  struct SequenceMatchAction {
      bool is_subroutine = false;
      std::string var_name;
      std::unique_ptr<ExpressionNode> expr;
      ...
  };
  using SequenceMatchAssignment = SequenceMatchAction;
  ```
- Updated `SequenceMatchItemNode` to store `std::vector<SequenceMatchAction> match_assignments`.
- Defined `PendingSubroutineCall`:
  ```cpp
  struct PendingSubroutineCall {
      std::string name;
      std::vector<LogicVal> args;
      std::string scope;
  };
  ```

### B. Parser Implementation (`CAS/src/frontend/parser_expr.cpp`)
- In `parse_primary()`:
  - Extended sequence match item parsing after `match(TokenType::TOKEN_COMMA)` to support both variable assignments (`var = expr`) and subroutine calls:
    - User subroutines with arguments: `log_transaction(in_val, rx_data)`
    - Subroutines without parentheses: `subroutine_name`
    - Package-scoped subroutines: `pkg::subroutine(...)`
    - System tasks: `$display(...)`, `$finish`, `$stop`
  - Constructed `SequenceMatchAction(true, name, std::make_unique<FunctionCallNode>(name, std::move(args)))`.

### C. Kernel Expression Evaluator (`CAS/include/kernel/expr_evaluator.hpp`, `CAS/src/kernel/expr_evaluator.cpp`)
- Added `pending_subroutines` pointer and getter/setter `set_pending_subroutines()`.
- In `ExprEvaluator::eval(SequenceMatchItemNode*)`:
  - When the underlying sequence condition matches (`!val.is_unknown() && val.is_true()`):
    - For assignments: evaluated RHS and updated `current_sva_local_vars`.
    - For subroutines: evaluated each argument expression in the active Preponed and local-variable context, and pushed `{a.var_name, evaluated_args, scope}` to `pending_subroutines`.
  - Replaced illegal evaluation outside sequence/property contexts with diagnostic `[CAS-DTINPCIL]`.

### D. Subroutine Execution & Diagnostic Enforcement (`CAS/include/engine.hpp`, `CAS/src/engine.cpp`)
- Added recursive inspector `subroutine_has_blocking_timing_control(const StatementNode* stmt)`:
  - Detects `DelayStatementNode`, `EventControlStatementNode`, `CycleDelayStatementNode`, `ForeverStatementNode`, `WaitForkStatementNode`, `WaitEventTriggeredStatementNode`, and nested task calls.
- Implemented `Engine::execute_sva_subroutine(name, args, scope)`:
  - Dispatches to functions (`eval_function`) or tasks (`TaskActivationFrame`).
  - Enforces `[CAS-DTINPCIL]` if any blocking timing controls are detected.

### E. Stratified Scheduler SVA Engine (`CAS/src/kernel/scheduler.cpp`)
- Bound `pending_subroutines` during Observed region evaluation.
- Cleared Preponed overrides and entered the Reactive region:
  - Executed all `pending_subroutines` via `engine.execute_sva_subroutine()`.
  - Executed completed thread pass/fail action blocks.
  - Flagged scheduler `activity = true` to trigger combinatorial propagation before Postponed `$monitor` execution.
