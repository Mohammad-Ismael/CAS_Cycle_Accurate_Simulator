## 1. Overview & Capabilities
Milestone v3.43.0.0 introduces full support for IEEE Std 1800-2023 §20.10, implementing standard severity system tasks (`$fatal`, `$error`, `$warning`, `$info`), standard severity level prefixes, hierarchical scope and source file/line location metadata reporting, optional finish number handling, simulation termination semantics on `$fatal`, execution in procedural and assertion action-block contexts, and context diagnostic `[CAS-DTINPCIL]`.

### Key Features Implemented:
1. **Severity System Tasks (§20.10)**:
   - Added lexer tokenization for keywords `$fatal`, `$error`, `$warning`, and `$info`.
   - Implemented AST representation `SeverityTaskStatementNode` capturing severity level (`FATAL`, `ERROR`, `WARNING`, `INFO`), optional `$fatal` finish number expression, format string, argument expressions, and source file/line attribution.
   - Parsed calls with optional empty parentheses (e.g. `$info;`), arguments only (`$warning("msg %0d", val);`), or `$fatal` with finish number (`$fatal(1, "msg");`).

2. **Standard Location & Hierarchical Scope Reporting (§20.10)**:
   - Output adheres strictly to Synopsys VCS standard severity header format:
     ```text
     <Severity>: "<source_file>", <line>: <hierarchical_scope>: at time <sim_time> <precision_unit>
     <Formatted message>
     ```
   - Accurately tracks simulation time scaled to active time precision (e.g. `25000 ps` for `` `timescale 1ns/1ps `` at time 25ns).
   - Formatted string evaluation with full conversion specifier support (`%0d`, `%0t`, `%0h`, `%s`, `%f`, etc.).

3. **Termination Semantics & Finish Numbers (§20.10)**:
   - `$fatal` unconditionally terminates the simulation, updating engine status and causing CAS CLI to return a non-zero exit code (code 1).
   - Evaluates optional finish number (valid values: 0, 1, 2) controlling diagnostic termination summary output.
   - Finish numbers outside 0..2 raise context diagnostic `[CAS-DTINPCIL]`.

4. **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
   - Enforced restriction that severity system tasks may only appear within procedural blocks (`initial`, `always`, `always_comb`, `always_ff`, `always_latch`, `final`), tasks, functions, or assertion action blocks.
   - Placement at compilation unit scope, module item scope, package scope, or class body scope is caught at parse time with context diagnostic:
     `[CAS-DTINPCIL] Dynamic type in non-procedural context: severity system task '<name>' is not permitted outside procedural or action-block context per IEEE 1800-2023 section 20.10`.
