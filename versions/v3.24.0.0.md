# Release v3.24.0.0: Virtual Interfaces in Object-Oriented Classes 'virtual interface [modport]', Dynamic Interface Handle Binding, Procedural Drives & Clocking Dereferencing, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §25.9)

## 1. Overview & Milestone Scope
This release delivers **v3.24.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **55.6%** and implementing full IEEE Std 1800-2023 compliance for:
- **§25.9 (Virtual Interfaces in Object-Oriented Classes)**:
  - **Virtual Interface Type Syntax & Grammar (§25.9)**:
    - Declaration syntax:
      ```systemverilog
      virtual [ interface_identifier ] [ . modport_identifier ] variable_identifier [ = init_expr ] ;
      ```
    - Supported across class member declarations, routine formal argument lists (`function` and `task`), local variable statements, and module-level items.
  - **Dynamic Interface Handle Binding & Modport Views (§25.9.1)**:
    - Dynamic assignment of physical interface instances or modports to virtual interface variables (`drv.vif = intf.drv_mp;`).
    - Allocation in dedicated high-range virtual interface handle space (`0x80000001` upwards) avoiding collision with integral data values.
    - Multi-stage hierarchical lookup (`Engine::lookup_virtual_interface`) resolving virtual interface handles across class instances (`this_obj`), active execution context frames, process call stacks, netlists, and physical interface instances.
  - **Procedural Drives & Signal Dereferencing (§25.9.2)**:
    - Non-blocking assignments through virtual interfaces: `vif.req <= 1'b1;`, `vif.addr <= a;`, `vif.wdata <= d;`.
    - Blocking assignments and handle transfers through virtual interfaces: `this.vif = target_vif;`, `vif.addr = a;`.
    - Member read access across modports and physical signals: `rb = vif.rdata;`, `if (vif.ready) ...`.
    - Intra-assignment and procedural timing event controls across virtual interfaces: `@(posedge vif.clk)`, resolving to physical clock nets through slice interconnects.
  - **Time-Consuming Class Task Activation Frames**:
    - Class task invocation preservation: `TaskActivationFrame` instances preserve object handle context (`this_obj`) across simulation time delays and event suspensions (`@(posedge ...)` and `#delay`), ensuring class state and member virtual interfaces resume seamlessly.
  - **Context Diagnostics & IEEE Semantic Restriction (`[CAS-DTINPCIL]`)**:
    - Prohibits continuous assignment driving through virtual interfaces or referencing virtual interfaces in continuous assignments:
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment driving through virtual interface ... is illegal per IEEE 1800-2023 section 25.9
      ```
    - Enforces runtime error on uninitialized / null virtual interface dereferencing:
      ```text
      [CAS-DTINPCIL] Null virtual interface dereference: attempted to access member ... on uninitialized virtual interface handle per IEEE 1800-2023 section 25.9
      ```

  - Task invocation (`TaskActivationFrame`): bound `cl_obj` as `frame.this_obj` during class method calls, restored `current_this` in `step_process`, and ensured clean clearing to `nullptr` when returning to root process execution.
