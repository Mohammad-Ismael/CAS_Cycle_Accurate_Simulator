## 1. Release Overview

CAS `v4.4.1.0` is a landmark usability and infrastructure release that standardizes the entire repository layout, introduces turnkey one-command setup and verification automation in `scripts/`, hardens the C++ preprocessor macro engine for complex RTL syntax, and ensures real-time stream flushing for file I/O operations (`$fwrite`) across discrete-event simulations.

With this release, any engineer can clone CAS and verify the full 112-suite regression suite, run all 1,028 IEEE 1800-2023 `sv-tests`, or boot a full 32-bit RISC-V SoC with a single command.

## 2. Key Capabilities Delivered in v4.4.1.0

### A. Clean, Standardized Repository Architecture
The repository has been restructured into dedicated, orthogonal functional directories:
1. **`regression_testing/`**:
   - Contains all **112 versioned milestone regression test suites** (`v1_0_0_0_shift_reg_core` through `v4_4_0_0_full_sv_tests_negative_diagnostics_parity`).
   - Houses `regression_testing/run_regressions.py` for automated multi-suite regression execution with 100% VCS golden parity verification.
2. **`projects/`**:
   - Dedicated strictly to **production real-world SoC and IP core verification targets** (`projects/ibex/`, `projects/ibex_simple_system/`).
   - Cleaned of all legacy, ad-hoc, and scratch test directories.
3. **`benchmarks/`**:
   - Dedicated to external standard compliance suites (`benchmarks/sv-tests/`).
   - Features `benchmarks/run_sv_tests.py` providing ultra-fast multi-threaded benchmark sweeps across all 1,028 positive and negative test cases.
4. **`scripts/`**:
   - Portable, zero-configuration automation scripts with dynamic path resolution (`REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`).

### B. Turnkey Automation (`scripts/`)
- **`scripts/setup_and_verify.sh`**:
  - One-command 3-stage validation pipeline:
    - **Stage 1**: Configures and compiles the CAS kernel and CLI binary in Release mode (`cmake --build CAS/build -j`).
    - **Stage 2**: Executes all 112 milestone regression suites via `regression_testing/run_regressions.py` (**112/112 PASS = 100.0%**).
    - **Stage 3**: Executes all 1,028 IEEE 1800-2023 `sv-tests` via `benchmarks/run_sv_tests.py` (**1,028/1,028 PASS = 100.0%** in ~11-15 seconds).
- **`scripts/run_ibex_demo.sh`**:
  - Turnkey runner for the lowRISC Ibex RV32IMC Simple System SoC.
  - Automatically ensures CAS is built, clones Ibex if not present, extracts compiler defines and include paths from `lowrisc_ibex_ibex_simple_system_0.vc`, boots `hello_test.vmem`, and validates UART log output:
    ```text
    Hello simple system
    DEADBEEF
    BAADF00D
    Tick!
    Tock!
    Tick!
    Tock!
    Tick!
    ```

### C. Preprocessor Macro Argument Tracking (IEEE 1800-2023 §22.5.1)
- In real-world RTL like Ibex, macros frequently pass concatenation expressions containing commas inside curly braces or brackets (e.g., `` `ASSERT(Foo, {a, b} == c) ``).
- Enhanced `CAS/src/frontend/lexer.cpp` macro argument splitting to track brace `{}` and bracket `[]` nesting depth, preventing commas within sub-expressions from being incorrectly treated as argument delimiters.

### D. Real-Time File I/O & Output Buffer Flushing
- Enhanced `CAS/src/kernel/evaluator.cpp` to automatically flush file handles (`fflush(fp)`) on `$fwrite`, `$display`, and simulation termination (`$finish`, `$stop`).
- Hardened `CAS/src/kernel/trace_buffer.cpp` and `CAS/src/kernel/scheduler.cpp` with real-time text packet and trace buffer flushes, ensuring that UART log files (such as `ibex_simple_system.log`) never lose trailing buffered output upon simulation exit.
