# Release v3.6.0.0: Constrained Randomization 'rand', 'randc', 'constraint' Blocks, 'randomize()', Inline 'with {}' Constraints, and Solver Contradiction Diagnostic '[CAS-CNST-CIF]'

## 1. Overview & Milestone Scope
This release delivers **v3.6.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **30.3%** and implementing full IEEE Std 1800-2023 compliance for:
- **§18.4 & §18.4.1 (Random Modifiers 'rand' and 'randc')**:
  - `rand data_type property_name;` declares standard random variables whose values are assigned uniformly across their valid domain during `.randomize()`.
  - `randc data_type property_name;` declares cyclic random permutation variables.
  - Properties not declared `rand` or `randc` are unaffected by solver passes and preserve their pre-randomization states.
- **§18.5 (Declarative 'constraint' Blocks)**:
  - Named constraint blocks defined within class bodies (`constraint c_name { ... }`).
  - Hierarchical inheritance of constraint blocks across base and derived classes.
  - Relational constraint expressions (`==`, `!=`, `<`, `<=`, `>`, `>=`).
  - Set membership and range containment expressions (`val inside { [low:high], item1, ... }`).
- **§18.7 (Inline Constraints 'randomize() with { ... }')**:
  - Subroutine calls allowing dynamic inline constraint blocks to augment or restrict class constraints during `.randomize()`.
  - Resolution of unqualified identifiers in inline blocks against class properties (`this.prop`) and local variables.
- **§18.6.3 & §18.14 (Contradiction Diagnostic '[CAS-CNST-CIF]' & Deterministic PRNG Seeding)**:
  - Solver contradiction detection: when interval domains become empty or mutually incompatible, `.randomize()` fails gracefully by returning `0` and leaving class properties unmutated.
  - Solver emits the diagnostic:
    `[CAS-CNST-CIF] Constraints inconsistency failure: Constraints are inconsistent and cannot be solved.`
  - Built-in `srandom(seed)` task enabling deterministic PRNG initialization (`this.srandom(32'h12345678)`) guaranteeing line-for-line golden parity with Synopsys VCS.
- **§18 & §21.2.3 (Dynamic Type Context Restrictions [CAS-DTINPCIL])**:
  - Continuous assignments and non-procedural `$monitor` expressions using `randomize()` are illegal per IEEE 1800-2023 §18 and trigger `[CAS-DTINPCIL]`.

## 2. IEEE Std 1800-2023 Semantics & Implementation Mechanics

### A. Random Modifiers & AST Representation (`CAS/include/frontend/ast_module.hpp`, `CAS/include/frontend/ast_expr.hpp`, `CAS/include/frontend/ast_stmt.hpp`)
- `ClassMemberVar` tags property random attributes:
  ```cpp
  struct ClassMemberVar {
      std::string name;
      uint32_t width = 32;
      bool is_signed = false;
      std::unique_ptr<ExpressionNode> default_expr;
      bool is_rand = false;
      bool is_randc = false;
  };
  ```
- `ConstraintBlockNode` encapsulates named constraint statements:
  ```cpp
  struct ConstraintBlockNode : public ASTNode {
      std::string name;
      std::vector<std::unique_ptr<ExpressionNode>> exprs;
  };
  ```
- `InsideNode` models value and range containment (`[lo:hi]`):
  ```cpp
  struct InsideRange {
      std::unique_ptr<ExpressionNode> low;
      std::unique_ptr<ExpressionNode> high;
  };

  struct InsideNode : public ExpressionNode {
      std::unique_ptr<ExpressionNode> target;
      std::vector<InsideRange> ranges;
  };
  ```
- `RandomizeCallNode` & `RandomizeStatementNode` model both functional and statement-level calls with optional inline constraint expressions:
  ```cpp
  struct RandomizeCallNode : public ExpressionNode {
      std::unique_ptr<ExpressionNode> target_handle;
      std::vector<std::unique_ptr<ExpressionNode>> inline_constraints;
  };
  ```

### B. Interval Domain Propagation & Contradiction Solver (`CAS/include/common/constraint_solver.hpp`)
- `ConstraintSolver` collects all `rand`/`randc` variables in declaration order from base to derived classes and initializes default domain intervals `[0 .. (2^width)-1]`.
- All declarative constraints and inline `with { ... }` constraints are accumulated and propagated to narrow domain bounds:
  - Equality (`==`): narrows `min_val` and `max_val` to target constant.
  - Inequalities (`>=`, `>`, `<=`, `<`): adjust lower and upper domain boundaries.
  - Range containment (`inside { [lo:hi] }`): bounds domain to the specified interval.
- Contradiction check:
  - If `min_val > max_val` for any variable, the solver prints diagnostic:
    `[CAS-CNST-CIF] Constraints inconsistency failure: Constraints are inconsistent and cannot be solved.`
  - The solver returns `false` (`0`) immediately without updating object properties.
- Value assignment:
  - For valid domains, values are selected via the deterministic LCG pseudo-random generator `chosen = min_val + (r % (max_val - min_val + 1))`.

### C. Deterministic PRNG Seeding (`CAS/include/common/class_types.hpp`, `CAS/src/kernel/evaluator.cpp`)
- `ClassObject` maintains instance-level PRNG state:
  ```cpp
  void srandom(uint32_t seed) { prng_state = seed; }
  uint32_t next_random() {
      prng_state = prng_state * 429 + 25;
      return prng_state >> 16;
  }
  ```
- Subroutine call `this.srandom(seed)` sets the PRNG seed inside constructors or methods, matching Synopsys VCS pseudo-random distribution.
