# Release v2.9.0.0: Dynamic Arrays, 'new[size]' Dynamic Allocation, Resize with Copy Constructor 'new[size](arr)', and Methods '.size()' / '.delete()'

## 1. Overview & Milestone Scope
This release delivers **v2.9.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§7.5 (Dynamic Arrays)**:
  - Declarations of dynamic arrays using empty dimension brackets (`data_type array_name [];`).
  - At time 0 (prior to runtime allocation), dynamic arrays are unallocated and `arr.size()` evaluates to 0.
- **§7.5.1 (Dynamic Array Allocation & Copy Constructor)**:
  - Dynamic allocation: `array_name = new[size_expr];` allocates contiguous memory for `size_expr` elements initialized to default 4-state unknown (`'x`).
  - Copy constructor & resize: `array_name = new[size_expr](source_arr);` allocates `size_expr` elements and copies up to `min(new_size, source_size)` elements from the source dynamic array. When resizing in-place (`arr = new[N](arr);`), existing elements are safely preserved and new trailing elements are initialized to default `'x`.
- **§7.5.3 (Built-in Dynamic Array Methods)**:
  - `arr.size()`: Returns current number of elements in the dynamic array as a 32-bit unsigned integer vector (`LogicVal::make_known(32, size)`).
  - `arr.delete()`: Empties the dynamic array, freeing memory and resetting its element count to 0.
- **§7.5.4 (Dynamic Array Indexing & 4-State Out-of-Bounds Semantics)**:
  - **RHS Read Subscript (`arr[index]`)**: Returns element at specified index. If `index < 0`, `index >= arr.size()`, or index contains any unknown (`'x`) or high-impedance (`'z`) bits, returns a 4-state unknown vector (`'x`) of the element bit-width (e.g. `8'hxx`).
  - **LHS Write Subscript (`arr[index] = val;`)**: Modifies element in-place. If index is out-of-bounds or unknown, the write is ignored with zero side-effects.
- **§7.5 & §21.2.3 (Dynamic Type Context Restrictions [CAS-DTINPCIL])**:
  - Continuous assignments to or from dynamic arrays or dynamic array subscripts are illegal in SystemVerilog. CAS compiles and elaborates with strict validation, emitting `[CAS-DTINPCIL]` (*Dynamic type in non-procedural context*).
  - Passing dynamic array variables or dynamic array subscripts directly into non-procedural `$monitor` expressions is illegal and produces `[CAS-DTINPCIL]`.
- **Top-Level Module Auto-Detection**:
  - Refined multi-file compilation module root resolution: in scenarios where multiple uninstantiated modules are ingested, root resolution prioritizes testbench conventions (`tb_`, `_tb`, `testbench`, `regression`) to guarantee automated top module binding without requiring explicit `--top` flags.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. DynamicArrayObject Representation (`CAS/include/common/dynamic_array_types.hpp`)
- Dynamic arrays are encapsulated in `DynamicArrayObject`:
  ```cpp
  struct DynamicArrayObject {
      std::string name;
      uint32_t elem_width = 32;
      bool is_signed = false;
      std::vector<LogicVal> elements;

      DynamicArrayObject() = default;
      DynamicArrayObject(std::string n, uint32_t w = 32, bool s = false)
          : name(std::move(n)), elem_width(w), is_signed(s) {}

      uint32_t size() const { return (uint32_t)elements.size(); }
      void allocate(size_t sz);
      void resize_and_copy(size_t sz, const DynamicArrayObject& src);
      void delete_all();
      LogicVal get_elem(int64_t idx) const;
      void set_elem(int64_t idx, const LogicVal& val);
  };
  ```

### B. Procedural Dynamic Allocation & Copy Constructor
- Allocation statements (`arr = new[size];` and `arr = new[size](arr);`) are parsed into `NewArrayNode` within expressions.
- During evaluation in `Evaluator::execute_statement()` and `ExprEvaluator::eval()`:
  - If a copy argument is supplied (`new[size](source)`), a temporary elements buffer is populated with elements from `source` up to `min(new_size, source.size())`, safely handling self-resizing `dyn_data = new[5](dyn_data)`.
  - Elements beyond the copy source length are initialized to default 4-state unknown (`LogicVal::make_x(elem_width)`).

### C. [CAS-DTINPCIL] Diagnostic Rules
- During elaboration (`Elaborator::elaborate_module`), continuous assignment LHS targets and RHS expressions are recursively inspected. Any reference to a dynamic array identifier, dynamic array subscript `arr[i]`, or dynamic array method produces diagnostic:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: dynamic array index select 'arr[]' used in continuous assignment per IEEE 1800-2023 section 7.5`
- During `$monitor` initialization, argument expressions are verified. Any direct dynamic array reference produces diagnostic:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: dynamic array index select 'arr[]' used in $monitor per IEEE 1800-2023 section 7.5 & 21.2.3`

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & Parser
- **Lexer (`lexer.hpp`, `lexer.cpp`)**: Added `TOKEN_NEW` (`new`) keyword tokenization.
- **AST Nodes (`ast_expr.hpp`, `ast_module.hpp`, `ast_stmt.hpp`)**:
  - Added `NewArrayNode` representing `new[size_expr]` and `new[size_expr](copy_expr)`.
  - Added `is_dynamic_array` flags to `PortNode` and `VarDeclStatementNode`.
- **Parser (`parser_module.cpp`, `parser_stmt.cpp`, `parser_expr.cpp`)**:
  - Parsed empty brackets `[]` as dynamic array declarations.
  - Parsed `new [ <expr> ]` and optional copy constructors `( <expr> )`.

### B. Kernel Elaborator & Engine
- Populated `Engine::dynamic_array_map` during hierarchical module elaboration.
- Added `is_dynamic_array()` and `get_dynamic_array()` lookup methods supporting both module-level signals and local frame dynamic variables.
- Auto-detected top-level root module with heuristics favoring testbenches (`tb_`, `_tb`, `testbench`, `regression`).

### C. Expression & Statement Evaluators
- Extended `ExprEvaluator` to evaluate `NewArrayNode`, dynamic array `.size()`, `.delete()`, and subscript reads `arr[idx]`.
- Implemented IEEE §7.5.4 4-state out-of-bounds safety returning `'x` on invalid reads and ignoring out-of-bounds writes.
- Added dynamic array statement interception in `Evaluator` and `StratifiedScheduler` avoiding invalid task lookup traps.
