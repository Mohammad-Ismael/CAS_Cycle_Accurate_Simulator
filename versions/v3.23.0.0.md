# Release v3.23.0.0: SystemVerilog Program Blocks 'program' / 'endprogram', Stratified Scheduler Reactive Region Scheduling, Implicit $exit Execution Semantics, Race-Free Testbench Partitioning, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §24)

## 1. Overview & Milestone Scope
This release delivers **v3.23.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **54.2%** and implementing full IEEE Std 1800-2023 compliance for:
- **§24 (SystemVerilog Program Blocks & Reactive Scheduling)**:
  - **Program Block Grammar & Syntax (§24.3)**:
    - Declaration syntax:
      ```systemverilog
      program [ automatic | static ] program_identifier [ ( [ list_of_ports ] ) ] ;
          { program_item }
      endprogram [ : program_identifier ]
      ```
    - Support for program header port lists, internal signals, variables, tasks, functions, and initial procedures.
  - **Stratified Scheduler Reactive Region Partitioning (§24.3 & §4.4.3)**:
    - Clear partitioning of execution domains: design processes execute in the Active region; testbench processes declared within program blocks execute in the Reactive region.
    - Race-free timing synchronization: program processes sampling design signals on clock edges observe the post-NBA committed values without non-deterministic delta races; program drives scheduled in the Reactive region take effect after design sampling has completed for that clock edge.
    - Time-wheel event partitioning (`due_reactive_pids`): procedural delays (`#delay`) within program blocks wake up directly in the Reactive region of their target time slots.
    - Dynamic reactive-to-active loopback: when reactive assignments drive design signals or wake active processes, the stratified scheduler loops back to the Active region to ensure global convergence before Postponed sampling.
  - **Implicit `$exit` Execution Semantics (§24.7)**:
    - Simulation completes cleanly when all `initial` processes within all program blocks have terminated, even if free-running clock generators or active `always` blocks remain in design modules.
    - Support for explicit `$exit` system task invocations to finish the calling program process immediately.
  - **Semantic Context Restrictions & Context Diagnostic (`[CAS-DTINPCIL]`)**:
    - Prohibits `always`, `always_ff`, `always_comb`, and `always_latch` constructs within program blocks per IEEE Std 1800-2023 §24.3.
    - Prohibits nested `module`, `interface`, or `program` declarations inside program scope.
    - Prohibits module, interface, or program instantiations inside program blocks.
    - Prohibits continuous assignments in program scope that drive external nets (e.g. output/inout ports or cross-scope nets).

### E. Stratified Scheduler Reactive Loop ([`scheduler.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/scheduler.hpp), [`scheduler.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp))
- Added `std::vector<uint32_t> due_reactive_pids;` to track time-wheel events scheduled by reactive processes.
- Updated [`StratifiedScheduler::resume_waiting_processes(bool for_reactive)`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp) to partition process wakeups:
  - `resume_waiting_processes(false)` resumes Active design processes.
  - `resume_waiting_processes(true)` resumes Reactive program processes.
- Implemented [`StratifiedScheduler::check_program_completion()`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp) to evaluate IEEE Std 1800-2023 §24.7 completion semantics:
  - Automatically terminates simulation when all program processes have reached completion (`bp.completed == true`).
- In [`StratifiedScheduler::execute_time_slot_delta_loop()`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp):
  - Sequenced: Active delta loop -> NBA update commitment -> Observed SVA evaluation -> Reactive region execution.
  - Reactive processes execute, resume waiting reactive threads, and invoke `propagate_comb()`. If reactive execution alters nets driving active processes, the delta loop loops back to the Active region.
- In [`StratifiedScheduler::run_simulation()`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp):
  - At Time 0: Active root processes run first; Reactive root processes run during the Reactive phase.
  - At each subsequent time slot: time-wheel events are partitioned into `due_active_pids` (stepped in Active region) and `due_reactive_pids` (stepped in Reactive region).
- In [`StratifiedScheduler::invoke_fork()`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp):
  - Child processes inherit `is_reactive` and `is_program_process` properties from parent processes.
- In [`Evaluator::execute_statement()`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/evaluator.cpp):
  - Handled `ExitStatementNode` by marking `bp.completed = true;`.
