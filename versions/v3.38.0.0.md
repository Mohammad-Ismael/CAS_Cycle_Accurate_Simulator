## 1. Overview & Capabilities
Milestone v3.38.0.0 introduces native support for IEEE Std 1800-2023 §8.21 abstract virtual classes, pure virtual subroutine declarations, and polymorphic dispatch through abstract base handles.

### Key Features Implemented:
1. **Abstract Class Declarations (`virtual class ... endclass`)**:
   - Parsed compilation-unit, package, and module-level `virtual class` declarations via `Parser::parse_class(bool is_interface_class, bool is_abstract)`.
   - Propagated `is_abstract` attribute on `ClassNode` and prevented direct instantiation via `new` with context diagnostic `[CAS-DTINPCIL]` per §8.21.
2. **Pure Virtual Subroutine Declarations (`pure virtual function/task ...;`)**:
   - Parsed method prototypes with `is_pure = true` in AST.
   - Enforced standard IEEE requirement restricting `pure virtual` declarations strictly to `virtual class` or `interface class` constructs, rejecting declarations in concrete classes with diagnostic `[CAS-DTINPCIL]`.
3. **Inheritance & Concrete Implementation Enforcement**:
   - In `elaborator.cpp`, validated that non-virtual classes extending abstract ancestor classes implement all inherited pure virtual tasks and functions.
   - Verified formal argument counts and directions between pure virtual prototypes and concrete implementations, throwing `[CAS-DTINPCIL]` on mismatches or missing implementations.
4. **Virtual Method Table (vtable) & Polymorphic Base Dispatch**:
   - Propagated virtual methods through the inheritance hierarchy in `elaborator.cpp`.
   - Dispatched tasks and functions dynamically using dynamic object type at runtime (`cl_obj->class_def->dispatch_task` and `dispatch_function`).
   - Supported unpacked arrays of class handles (`base_driver drivers[2];`), storing object handle IDs and indexing correctly during method invocations.
5. **Call Frame PC Coordination**:
   - Corrected subroutine activation frame program counter advancement (`bp.call_stack.back().pc++`) in `StratifiedScheduler::invoke_task` during statement-level function invocations, preventing infinite execution loops when subroutines invoke helper methods.
