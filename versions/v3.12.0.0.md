# Release v3.12.0.0: Direct Programming Interface (DPI-C: 'import "DPI-C"', 'pure' Functions, C ABI Parameter Marshalling, Dynamic Linking, and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.12.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **38.8%** and implementing full IEEE Std 1800-2023 compliance for:
- **§35 (Direct Programming Interface DPI-C)**:
  - **DPI-C Import Declarations (§35.4 & §35.5)**:
    - `import "DPI-C" [pure | context] [c_identifier =] function [data_type] function_identifier ( [tf_port_list] );`
    - `import "DPI-C" [context] [c_identifier =] task task_identifier ( [tf_port_list] );`
    - Distinguishes compilation-unit scope imports from module-scope imports.
    - Honors `pure` qualifier for side-effect-free functions whose return values depend solely on their input arguments.
    - Supports default C function symbol names and explicit `c_identifier =` mappings.
  - **Standard C ABI Data Type Mapping (§35.5.6)**:
    - 2-state integer scalar and vector mappings:
      - `byte` <-> `int8_t` / `char`
      - `shortint` <-> `int16_t` / `short`
      - `int`, `integer` <-> `int32_t` / `int`
      - `longint` <-> `int64_t` / `long long`
      - `bit`, `logic` <-> `uint32_t` / integer scalars
    - Call-by-value argument marshalling from CAS 4-state/2-state `LogicVal` into standard native C argument registers.
    - Return value marshalling from C foreign returns back into typed CAS `LogicVal`.
  - **Dynamic Shared Library Resolution & Symbol Binding**:
    - Automatic loading of compiled foreign model libraries (`c_model.so` / `c_model.dll`) via dynamic linker primitives (`dlopen`, `dlsym`, `dlclose`).
    - Multi-path resolution probing working directory, source directories, and project paths.
    - Native ABI function pointer casting dispatching 0 to 6 arguments for `void`, `int32_t`, and `int64_t` return signatures.
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects DPI-C foreign function calls in continuous assignments (`assign`) during elaboration with `[CAS-DTINPCIL]`.
    - Rejects DPI-C foreign function calls in persistent `$monitor` argument lists with `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Nodes (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`, `CAS/include/frontend/ast_module.hpp`)
- Added tokens: `TOKEN_IMPORT` (`import`), `TOKEN_PURE` (`pure`), `TOKEN_CONTEXT` (`context`), and `TOKEN_VOID` (`void`).
- Defined AST node `DpiImportNode`:
  ```cpp
  struct DpiImportNode : public ASTNode {
      std::string sv_name;
      std::string c_name;
      bool is_pure = false;
      bool is_context = false;
      bool is_task = false;
      std::string return_type = "int";
      uint32_t return_width = 32;
      bool return_signed = true;
      std::vector<PortNode> tf_ports;

      DpiImportNode() = default;
  };
  ```
- Added `dpi_imports` and `dpi_import_map` to `ModuleNode` and `Parser`.

### B. Parser Enhancements (`CAS/include/frontend/parser.hpp`, `CAS/src/frontend/parser_module.cpp`)
- Implemented `Parser::parse_dpi_import()` supporting:
  - Top-level compilation unit DPI imports in `Parser::parse_all()`.
  - Module-level DPI imports inside `module ... endmodule`.
  - Optional `pure` and `context` properties.
  - Explicit foreign name binding `c_identifier =`.
  - Return types (`void`, `int`, `byte`, `shortint`, `longint`, `bit`, `logic` with ranges).
  - Formal argument lists with directional qualifiers (`input`, `output`, `inout`).
  - Integer module-level signal declarations (`int hash_res = 0;`).

### C. Dynamic Linking & Foreign Dispatch Engine (`CAS/include/common/dpic_types.hpp`, `CAS/include/engine.hpp`)
- Implemented `DpiRegistry`:
  - Dynamically loads `./c_model.so` using `dlopen(path, RTLD_NOW | RTLD_GLOBAL)`.
  - Caches resolved symbol pointers via `dlsym(handle, symbol_name)`.
  - Automatically searches project source paths and current directories.
- In `ExprEvaluator` (`CAS/src/kernel/expr_evaluator.cpp`):
  - `eval_dpi_call(DpiImportNode* dpi, const std::vector<LogicVal>& evaluated_args)`:
    - Extracts `LogicVal` data bits into native integer buffers.
    - Dispatches to foreign function pointers:
      - 32-bit: `reinterpret_cast<int(*)(int, int)>(sym)(arg0, arg1)`
      - 64-bit: `reinterpret_cast<int64_t(*)(int64_t, int64_t)>(sym)(arg0, arg1)`
      - Tasks/void: `reinterpret_cast<void(*)(int)>(sym)(arg0)`
    - Constructs return `LogicVal` conforming to `return_width`.
- In `Evaluator` (`CAS/src/kernel/evaluator.cpp`):
  - Dispatches procedural statement DPI-C task calls (`TaskCallNode`).

### D. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`)
- Enforces `[CAS-DTINPCIL]` on continuous assignment:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: DPI-C foreign function 'c_calc_hash' used in continuous assignment per IEEE 1800-2023 section 35`
- Enforces `[CAS-DTINPCIL]` on persistent `$monitor`:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: DPI-C foreign function 'c_calc_hash' used directly in $monitor per IEEE 1800-2023 section 35 & 21.2.3`
