# Release v3.26.0.0: Hierarchical 'defparam' Statements, Instance-by-Name Parameter Assignment '#(.PARAM(val))', Elaboration-Time Constant Dependency Propagation, Out-of-Module Parameter Overrides, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §6.20 & §23.10)

## 1. Overview & Milestone Scope
This release delivers **v3.26.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **58.4%** and implementing full IEEE Std 1800-2023 compliance for:
- **§23.10 (Overriding Module Parameters)**:
  - **Hierarchical 'defparam' Statements (§23.10.1)**:
    - Declaration syntax:
      ```systemverilog
      defparam hierarchical_parameter_identifier = constant_mintypmax_expression { , hierarchical_parameter_identifier = constant_mintypmax_expression } ;
      ```
    - Overrides module parameters across arbitrary hierarchical module boundaries (e.g. `defparam top.nested_inst.stage_inst.WIDTH = 16;`).
    - Multi-pass constant evaluation resolving dependencies between parameters and cascading into downstream `localparam` values.
  - **Instance Parameter Assignment by Name (§23.10.2)**:
    - Instantiation syntax:
      ```systemverilog
      module_name #(.PARAM_A(val_a), .PARAM_B(val_b)) instance_name ( ... );
      ```
    - Precedence: `defparam` overrides take precedence over instantiation-site `#(...)` bindings, which take precedence over module declaration defaults.
  - **Localparam Dependency Cascades (§6.20)**:
    - Re-evaluation of `localparam` expressions (e.g., `localparam int MASK = (1 << WIDTH) - 1;`) based on overridden parameter values before port and signal net sizing.
    - Sizing of ports (`[WIDTH-1:0]`), internal nets, and registers according to the finalized parameter values.
  - **Context Diagnostics & Semantic Restriction (`[CAS-DTINPCIL]`)**:
    - Prohibits `defparam` statements inside procedural scopes (`initial`, `always`, `task`, `function`):
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: 'defparam' statement is illegal inside procedural scope per IEEE 1800-2023 section 23.10.1
      ```
    - Prohibits `defparam` targeting a `localparam`:
      ```text
      [CAS-DTINPCIL] defparam cannot override localparam 'PARAM' on hierarchical path ... per IEEE 1800-2023 section 6.20.4 & 23.10.1
      ```
    - Rejects non-existent hierarchical instance or parameter paths:
      ```text
      [CAS-DTINPCIL] defparam targets non-existent hierarchical path ... per IEEE 1800-2023 section 23.10.1
      ```

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexing & AST ([`lexer.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/lexer.hpp), [`lexer.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/lexer.cpp), [`ast_module.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/ast_module.hpp))
- Added `TokenType::TOKEN_DEFPARAM` keyword token in `lexer.hpp` and `lexer.cpp`.
- Extended `ParameterDef` in `ast_module.hpp` with `bool is_localparam` to distinguish `localparam` from configurable `parameter`.
- Added `DefparamItemNode` representing hierarchical assignments (`hierarchical_path`, `value_expr`, `declaring_file`, `declaring_line`).
- Added `std::vector<DefparamItemNode> defparams;` to `ModuleNode`.

### B. Frontend Parsing ([`parser_module.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_module.cpp), [`parser_stmt.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_stmt.cpp))
- In `parser_stmt.cpp`: Enforced diagnostic `[CAS-DTINPCIL]` if `defparam` is encountered in procedural statements.
- In `parser_module.cpp`:
  - Parsed `TOKEN_DEFPARAM` in module bodies, capturing comma-separated hierarchical assignments into `mod->defparams`.
  - In header parameters and module body parameters, recorded `is_localparam` and skipped type qualifiers (`int`, `logic`, `byte`, `unsigned`, etc.).

### C. Kernel Elaboration Engine ([`elaborator.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/elaborator.hpp), [`elaborator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/elaborator.cpp))
- In `Elaborator::elaborate`:
  - Phase 1: Mapped design hierarchy (`instance_to_module`) across top-level design tree.
  - Phase 2: Collected all `defparam` declarations across all instantiated modules into `pending_defparams`.
  - Phase 3: Resolved target instance paths and validated existence and parameter mutability (`!p.is_localparam`).
  - Phase 4: Ran multi-pass constant evaluation until fixed point, populating `defparam_overrides[target_scope][target_param]`.
- In `Elaborator::elaborate_module`:
  - Checked `defparam_overrides` first, prioritizing `defparam` over `#(...)` overrides.
  - Sized ports and internal nets using evaluated parameter maps per instance.
  - Extended `eval_const_expr` with bitwise and arithmetic operations (`|`, `&`, `^`, `/`, `%`).
