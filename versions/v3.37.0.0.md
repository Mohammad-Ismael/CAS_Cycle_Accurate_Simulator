# Release v3.37.0.0: Unique, Unique0, and Priority Case/If Decision Statements 'unique if', 'unique0 if', 'priority if', 'unique case', 'unique0 case', 'priority case', Runtime Completeness/Exclusivity Checks, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §12.5)

## 1. Overview & Milestone Scope
This release delivers **v3.37.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **73.8%** (`[████████████████████████████████████████░░░░░░] 73.8%`) and implementing full IEEE Std 1800-2023 compliance for:
- **Decision Statement Grammar & AST (§12.5)**:
  - Decision modifiers (`unique`, `unique0`, `priority`) prefixing `if` or `case`/`casex`/`casez` statements.
  - Tracking modifier state, source file, and line attributes on `IfStatementNode` and `CaseStatementNode`.
  - Null statement support (`statement_or_null`) parsing empty `;` blocks.
- **Evaluation & Runtime Violation Checking (§12.5.3 & §12.5.4)**:
  - Flattening and evaluating conditional `if-else-if` chains governed by leading `priority`, `unique`, or `unique0` modifiers.
  - `priority if` / `priority case`: evaluating conditions in order and executing first match; reporting completeness violation if no condition matches and no `else`/`default` exists (`RT-VIOLATION: priority if/case condition failed to match`).
  - `unique if` / `unique case`: checking exclusivity across all branches and reporting exclusivity violation if more than one condition matches (`RT-VIOLATION: unique if/case multiple conditions matched simultaneously`); reporting completeness violation if no condition matches and no `else`/`default` exists (`RT-VIOLATION: unique if/case condition failed to match`).
  - `unique0 if` / `unique0 case`: checking exclusivity across all branches and reporting exclusivity violation if more than one condition matches; allowing zero matches without error.
  - IEEE §12.5.3 & §12.5.4 unknown handling: suppressing run-time violation reports whenever selector or condition evaluates to any value containing X or Z.
- **Context Diagnostics & Semantic Restrictions (`[CAS-DTINPCIL]`)**:
  - Enforcing modifier placement exclusively before `if` or `case` statements: `[CAS-DTINPCIL] Dynamic type in non-procedural context: '<keyword>' modifier can only prefix an 'if' or 'case' statement per IEEE 1800-2023 section 12.5`.
  - Prohibiting decision modifiers outside procedural or generate block statements at module level: `[CAS-DTINPCIL] Dynamic type in non-procedural context: '<keyword>' modifier is not permitted outside procedural or generate block statements per IEEE 1800-2023 section 12.5`.
