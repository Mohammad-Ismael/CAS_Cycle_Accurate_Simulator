# Release v1.6.0.0: Intra-Assignment Timing Controls & Stratified Parity

## 1. Overview & Milestone Scope
This release delivers **v1.6.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§10.6.1 (Intra-Assignment Timing Controls)**: Both non-blocking (`target <= #delay rhs;`) and blocking (`target = #delay rhs;`) intra-assignment timing controls.
- **§4.4 (Stratified Event Scheduling)**: Strict region separation between Active thread execution, NBA queue commits, and Postponed `$monitor` sampling.
- **§21.2.2 ($monitor Task)**: Filtered value change detection ensuring `$time` formatting does not trigger spurious monitor firings.

---

## 2. Key Architecture Achievements & Refactorings

### A. Intra-Assignment Grammar & Parsing (§10.6.1)
- **`BlockingAssignNode` & `NonBlockingAssignNode`**:
  - Added native `intra_delay` fields without introducing virtual method overhead or AST bloat.
- **Parser Production Rules**:
  - Updated `Parser::parse_statement()` to recognize `#<delay>` immediately following assignment operators (`=` and `<=`).

### B. Dual-Phase Scheduling Pipeline
- **Non-Blocking Intra-Delays**:
  - RHS is evaluated immediately in the current Active region.
  - The resulting value and target are queued into `delayed_nba_queue` indexed by timestamp $(T + \text{delay})$.
  - The executing process does not suspend, maintaining zero simulation time execution.
  - At timestamp $(T + \text{delay})$, matured updates transfer into `nba_queue` to commit strictly during the NBA region.
- **Blocking Intra-Delays**:
  - RHS is sampled immediately in the current Active region.
  - The thread suspends execution, scheduling resumption and LHS commit at $(T + \text{delay})$ via `delayed_blocking_queue`.

### C. 100% VCS Parity & Monitor Event Discipline
- Validated on `tb_v1_6_0_0_regression` and multi-process concurrency stress tests against Synopsys VCS 2025.06-SP1.
- Full line-by-line output and event ordering parity achieved across all time slots.
