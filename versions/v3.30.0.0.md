# Release v3.30.0.0: Specify System Timing Checks ($setup, $hold, $width, $recovery), Timing Violation Logging, Notifier Toggling / X-Corruption, and Procedural Driver Exclusivity '[CAS-ICPD]' (IEEE Std 1800-2023 §31.8 & §32.7)

## 1. Overview & Milestone Scope
This release delivers **v3.30.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **64.0%** and implementing full IEEE Std 1800-2023 compliance for:
- **§31.8 & §32.7 (Specify System Timing Checks)**:
  - System timing check declarations inside specify blocks:
    - `$setup(data_event, reference_event, limit [, [ notifier ] ]);`
    - `$hold(reference_event, data_event, limit [, [ notifier ] ]);`
    - `$width(reference_event, limit [, threshold [, [ notifier ] ] ]);`
    - `$recovery(reference_event, data_event, limit [, [ notifier ] ]);`
  - Event terminals supporting `posedge`, `negedge`, and edge-less (`ANY`) transition monitoring.
  - Limit and threshold parameter evaluation scaled by timescale ratio.
  - Active time-wheel delta cycle tracking of last transition timestamps (`t_last_ref`, `t_last_data`).
  - Standard IEEE timing violation reporting to stdout:
    ```text
    "<file>", <line>: Timing violation in <hierarchical_scope>
        $setup( <data_name>:<t_last_data>, <edge> <ref_name>:<t_ref>, limit: <limit> );
    ```
  - Notifier variable toggling upon timing check violation:
    - Toggles 1-bit notifier variable (`0 -> 1` or `1 -> 0`), which triggers downstream corruption processes (e.g. `always @(notifier) q <= 1'bx;`) in the Stratified Scheduler active region with zero delta delay.
- **Single Procedural Driver Rule Enforcement (`[CAS-ICPD]`)**:
  - Enforced IEEE Std 1800-2023 §9.2.2.4:
    - Variables driven on the left-hand side of assignments within `always_ff`, `always_comb`, or `always_latch` procedures cannot be written to by any other process or assignment.
    - If detected during elaboration, throws:
      ```text
      [CAS-ICPD] Illegal combination of procedural drivers: variable '<name>' driven in 'always_ff'/'always_comb' cannot be driven by multiple processes
      ```
- **Context Diagnostics & Semantic Restrictions (`[CAS-DTINPCIL]`)**:
  - Prohibits timing check system tasks (`$setup`, `$hold`, `$width`, `$recovery`) outside `specify ... endspecify` blocks (e.g. inside `initial`, `always`, `task`, `function`, package, class, or module scope):
    ```text
    [CAS-DTINPCIL] Dynamic type in non-procedural context: timing check system task '<name>' is not permitted outside specify block per IEEE 1800-2023 section 31.8 & 32.7
    ```

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexing & AST ([`lexer.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/lexer.hpp), [`lexer.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/lexer.cpp), [`timing_check_types.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/common/timing_check_types.hpp), [`ast_module.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/ast_module.hpp))
- Added `TokenType::TOKEN_SYS_SETUP`, `TOKEN_SYS_HOLD`, `TOKEN_SYS_WIDTH`, and `TOKEN_SYS_RECOVERY`.
- Defined `TimingCheckType` (`SETUP`, `HOLD`, `WIDTH`, `RECOVERY`) and `TimingCheckEdge` (`ANY`, `POSEDGE`, `NEGEDGE`).
- Defined `TimingCheckEvent` and `TimingCheckNode` structs.
- Extended `ModuleNode` with `std::vector<std::shared_ptr<TimingCheckNode>> timing_checks;`.

### B. Frontend Parsing ([`parser_module.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_module.cpp), [`parser_stmt.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_stmt.cpp))
- In `Parser::parse_module()`:
  - Inside specify blocks: parsed `$setup`, `$hold`, `$width`, `$recovery` with event edge specifiers, limit expressions, thresholds, and optional notifiers into `mod->timing_checks`.
  - Outside specify blocks: enforced diagnostic `[CAS-DTINPCIL]` if timing check system tasks are encountered.
  - Stored declaration initial expression in `PortNode.default_value` for static netlist initialization.
- In `Parser::parse_statement()`: enforced diagnostic `[CAS-DTINPCIL]` rejecting timing check tasks inside procedural blocks.
- In `Parser::parse_class()` and `Parser::parse_package()`: enforced diagnostic `[CAS-DTINPCIL]` rejecting timing check tasks.

### C. Kernel Elaboration & Multi-Driver Validation ([`netlist.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/netlist.hpp), [`elaborator.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/elaborator.hpp), [`elaborator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/elaborator.cpp), [`engine.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/engine.hpp), [`engine.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/engine.cpp))
- Defined `RuntimeTimingCheck` struct (`type`, `scope`, `file`, `line`, `ref_net_id`, `data_net_id`, `limit_ticks`, `notifier_net_id`, `t_last_ref`, `t_last_data`, `last_ref_change_counter`, `last_data_change_counter`).
- In `Elaborator::elaborate_module`:
  - Resolved reference, data, and notifier terminal identifiers against the module scope.
  - Scaled limits and thresholds by timescale multiplier (`Lexer::get_timescale_ratio()`).
  - Initialized static net values for signals with declaration initial values (`default_value`).
  - Remapped all terminal net IDs through DSU canonical net map.
- In `Elaborator`: validated driver exclusivity per §9.2.2.4 throwing `[CAS-ICPD]` if an `always_ff`/`always_comb` driven variable has multiple procedural drivers or continuous assignments.
- Loaded timing check descriptors into `Engine::timing_checks`.

### D. Kernel Scheduling & Timing Check Engine ([`scheduler.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/scheduler.hpp), [`scheduler.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp))
- Implemented `StratifiedScheduler::evaluate_timing_checks()`:
  - Tracks transition change counters on reference and data signals across delta cycles.
  - Evaluates `$setup`, `$hold`, `$width`, and `$recovery` inequalities on triggering edges.
  - Prints standard IEEE compliance violation diagnostics to stdout.
  - Toggles associated notifier net, causing immediate active-region delta wakeup.
- In `StratifiedScheduler::evaluate_sequential_blocks()`:
  - Added support for `EdgeType::LEVEL` sensitivity, allowing `always @(notifier)` and level-sensitive processes to fire upon signal transitions.
- In `StratifiedScheduler::execute_time_slot_delta_loop()`:
  - Evaluated timing checks within the active region loop whenever signals change.
  - Cleaned initial net simulation state at T=0 (`n.prev_value = n.value; n.modified = false;`).
