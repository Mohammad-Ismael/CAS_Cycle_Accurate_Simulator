# Release v3.28.0.0: Built-in Gate Primitives, Tri-State Control Gates, User-Defined Primitives (UDPs), Contention Resolution, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §28 & §29)

## 1. Overview & Milestone Scope
This release delivers **v3.28.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **61.2%** and implementing full IEEE Std 1800-2023 compliance for:
- **§28 (Built-in Gate & Tri-State Primitives)**:
  - Multi-input logic gates: `and`, `nand`, `or`, `nor`, `xor`, `xnor`, `buf`, `not`.
  - Tri-state control gates: `bufif0`, `bufif1`, `notif0`, `notif1`.
  - IEEE Tables 28-5 & 28-6 compliant 4-state control evaluation.
  - Multi-driver resolution on shared net targets (active value vs `'z'`, opposing active values resolving to `'x'`).
- **§29 (User-Defined Primitives - UDPs)**:
  - Declarations: `primitive ... table ... endprimitive` with ANSI and non-ANSI port lists.
  - Combinational truth tables supporting symbols `'0'`, `'1'`, `'x'`, don't-care `'?'`, binary `'b'`, and retain `'-'`.
  - Evaluation fallback to `'x'` for unspecified input combinations per IEEE §29.3.
- **Context Diagnostics & Semantic Restrictions (`[CAS-DTINPCIL]`)**:
  - Prohibits gate or UDP primitive instantiations inside procedural scopes (`initial`, `always`, `task`, `function`):
    ```text
    [CAS-DTINPCIL] Dynamic type in non-procedural context: gate or primitive instantiation is not permitted inside procedural scope per IEEE 1800-2023 section 28 & 29
    ```
  - Prohibits gate or primitive output terminals connected to variables or `reg`:
    ```text
    [CAS-DTINPCIL] Dynamic type in non-procedural context: gate or primitive output cannot drive variable/reg '<scoped_name>' per IEEE 1800-2023 section 28 & 29
    ```
