# Release v3.13.0.0: Direct Programming Interface (DPI-C: 'export "DPI-C"', Context Functions 'context', 'svScope' Scope Resolution, Bidirectional C-to-SV Execution, and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.13.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **40.2%** and implementing full IEEE Std 1800-2023 compliance for:
- **§35.5.3, §35.6, §35.7 (DPI-C Exports, Context Subroutines, and svScope Resolution)**:
  - **DPI-C Export Declarations (§35.6)**:
    - `export "DPI-C" [c_identifier =] function function_identifier;`
    - `export "DPI-C" [c_identifier =] task task_identifier;`
    - Exports SystemVerilog tasks or functions to foreign C code using standard C calling conventions.
    - Resolves exported functions in module, interface, and package scopes.
    - Enforces VCS error `[DPI-FNF]` when exported function/task is undeclared in the containing scope.
  - **Context Functions & Tasks (§35.5.3)**:
    - `context` qualifier indicates a DPI-C subroutine that calls exported SystemVerilog subroutines or interacts with simulation state/scope.
    - Dynamic scope tracking using RAII guard (`ContextScopeGuard`) preserving and restoring calling scope across recursive foreign boundaries.
  - **DPI Scope Handling API (§35.7 & Annex I.8)**:
    - `svScope svGetScope(void)`: Returns handle to the current active SystemVerilog scope.
    - `svScope svSetScope(const svScope scope)`: Sets the current active scope for subsequent exported function calls and returns the previous scope handle.
    - Exported C ABI runtime symbols: `svGetScope`, `svSetScope`, and trampoline functions `sv_write_reg`, `sv_read_reg`.
  - **Bidirectional C-to-SV Execution**:
    - High-performance marshalling bridging C parameter registers into CAS `LogicVal` execution environment.
    - Subroutine return value forwarding (`return` statements in procedural function bodies).
    - Scope-aware memory and array access (`memory[addr & 3'b111] = data`).
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects DPI-C exported function calls in continuous assignments (`assign`) during elaboration with `[CAS-DTINPCIL]`.
    - Rejects DPI-C exported function calls in persistent `$monitor` argument lists with `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Nodes (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`, `CAS/include/frontend/ast_module.hpp`)
- Added tokens: `TOKEN_EXPORT` (`export`), `TOKEN_PLUS_PLUS` (`++`), `TOKEN_MINUS_MINUS` (`--`).
- Defined AST node `DpiExportNode`:
  ```cpp
  struct DpiExportNode : public ASTNode {
      std::string sv_name;
      std::string c_name;
      bool is_task = false;
      DpiExportNode() = default;
  };
  ```
- Added `dpi_exports` and `dpi_export_map` to `ModuleNode` and `Parser`.
- Extended `VarDeclStatementNode` with optional `init_expr` for inline procedural initializations (`int i = 0;`).

### B. Parser Enhancements (`CAS/include/frontend/parser.hpp`, `CAS/src/frontend/parser_module.cpp`, `CAS/src/frontend/parser_stmt.cpp`, `CAS/src/frontend/parser_function.cpp`)
- Implemented `Parser::parse_dpi_export()` supporting:
  - Compilation-unit level and module-level `export "DPI-C"` declarations.
  - Optional `c_identifier =` explicit foreign binding.
  - Syntax validation distinguishing `function` and `task` exports.
  - Verification that exported routines exist in the declaring scope.
- Enhanced statement parser:
  - Recognizes `int`, `byte`, `shortint`, `longint` procedural variable declarations with optional inline initialization (`init_expr`).
  - Implemented `for` loop step support for `i++` and `i--` in addition to `i = expr`.
  - Implemented standalone procedural increment (`ident++;`) and decrement (`ident--;`) statements.
- Enhanced function parser:
  - Supports `void` return types and standard integer types (`int`, `byte`, `shortint`, `longint`) in formal port lists.

### C. DPI-C Context, Scope Management, and Runtime Trampolines (`CAS/include/common/dpic_types.hpp`, `CAS/src/engine.cpp`, `CAS/src/kernel/expr_evaluator.cpp`)
- Defined `svScope` and context tracker in `DpiRegistry`:
  ```cpp
  typedef void* svScope;
  struct SvScopeContext {
      std::string scope_name;
  };
  ```
- Exported global C runtime symbols with `-rdynamic` (`ENABLE_EXPORTS ON` in CMake):
  - `svGetScope()`: returns active `svScope`.
  - `svSetScope(scope)`: switches active `svScope`.
  - `sv_write_reg(addr, data)`: trampolines into `Engine::dispatch_dpi_export`.
  - `sv_read_reg(addr)`: trampolines into `Engine::dispatch_dpi_export`.
- RAII Scope Guard in `ExprEvaluator::eval_dpi_call`:
  - When `dpi->is_context` is true, automatically binds calling scope before foreign invocation and restores prior scope on return.
- `Engine::dispatch_dpi_export`:
  - Resolves target function in active `svScope` context.
  - Passes marshalled `LogicVal` arguments into `eval_function`.
  - Propagates return value back to foreign caller.

### D. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`)
- Enforces `[CAS-DTINPCIL]` on continuous assignment:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: DPI-C exported function 'f_exp' used in continuous assignment per IEEE 1800-2023 section 35`
- Enforces `[CAS-DTINPCIL]` on persistent `$monitor`:
  `[CAS-DTINPCIL] Dynamic type in non-procedural context: DPI-C exported function 'f_exp' used directly in $monitor per IEEE 1800-2023 section 35 & 21.2.3`
