# Release v3.14.0.0: Direct Programming Interface (DPI-C: Opaque Pointer Storage 'chandle', 'null' Comparisons, 64-bit Pointer ABI Marshalling, and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.14.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **41.6%** and implementing full IEEE Std 1800-2023 compliance for:
- **§35.5.4 & §6.11 (DPI-C Opaque Pointer Storage 'chandle')**:
  - **Machine-Level Pointer Storage**:
    - `chandle` data type representing opaque machine-level foreign pointers (`void*`).
    - Allocation in module scopes, procedural scopes, task/function local frames, and DPI-C import/export port lists.
    - Default power-on initialization to `null` (64-bit known zero representation).
  - **`null` Keyword Recognition & Comparison**:
    - Syntactic recognition of `null` literal in assignments (`session_ptr = null;`) and conditions.
    - Binary equality (`==`, `===`) and inequality (`!=`, `!==`) between two `chandle` identifiers and between a `chandle` identifier and `null`.
    - Prohibits direct arithmetic, bit-slicing, and indexing operations on `chandle`.
  - **64-bit Native Pointer ABI Marshalling**:
    - High-performance x86_64 Calling Convention register preservation (`rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`).
    - Pass raw 64-bit memory addresses (`uintptr_t`) directly into foreign C functions without 32-bit truncation.
    - Foreign function return value casting: foreign functions returning `void*` cast untruncated 64-bit heap addresses into CAS 64-bit `LogicVal`.
    - Void tasks: DPI-C subroutines returning `void` execute safely without unpacking non-existent return registers.
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects `chandle` identifiers appearing in continuous assignments (`assign`) during elaboration with `[CAS-DTINPCIL]` (exempting equality checks against `null`).
    - Rejects continuous assignments driving `chandle` variables with `[CAS-DTINPCIL]`.
    - Rejects bare `chandle` identifiers in persistent `$monitor` argument lists with `[CAS-DTINPCIL]`, while permitting binary equality checks against `null` (`(session_ptr == null)`).

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Nodes (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`, `CAS/include/frontend/ast_module.hpp`, `CAS/include/frontend/ast_stmt.hpp`)
- Added token: `TOKEN_CHANDLE` (`chandle`).
- Extended AST nodes with chandle awareness:
  - `PortNode`: Added `bool is_chandle = false;`
  - `VarDeclStatementNode`: Added `bool is_chandle = false;`

### B. Parser Enhancements (`CAS/src/frontend/parser_module.cpp`, `CAS/src/frontend/parser_stmt.cpp`)
- Module Item & Port Parsing (`CAS/src/frontend/parser_module.cpp`):
  - Supported `chandle` in ANSI and non-ANSI module port lists (`is_chandle = true, width = 64`).
  - Supported `chandle` in module-level signal declarations with optional `null` initialization (`chandle session_ptr = null;`).
  - Supported `chandle` return type and formal argument types in `parse_dpi_import()`.
- Procedural Statement Parsing (`CAS/src/frontend/parser_stmt.cpp`):
  - Recognized `chandle` in procedural variable declarations, configuring 64-bit width and marking `is_chandle = true`.

### C. Kernel Architecture & Netlist Representation (`CAS/include/kernel/netlist.hpp`, `CAS/include/kernel/execution_context.hpp`, `CAS/include/kernel/elaborator.hpp`, `CAS/include/engine.hpp`)
- `Net`: Added `bool is_chandle = false;`
- `LocalVar`: Added `bool is_chandle = false;`. Initialized `chandle` local variables with `LogicVal(64, 0, 0)`.
- `ElaborationResult` & `Engine`: Added `std::unordered_set<std::string> chandle_names;` and `bool is_chandle(name, scope) const;` helper.

### D. DPI-C x86_64 Pointer ABI Marshalling (`CAS/src/kernel/expr_evaluator.cpp`)
- Replaced 32-bit `int` argument casting in `eval_dpi_call` with untruncated 64-bit `uint64_t` registers:
  ```cpp
  std::vector<uint64_t> c_args;
  for (size_t i = 0; i < evaluated_args.size(); ++i) {
      const auto& v = evaluated_args[i];
      c_args.push_back(v.is_real ? static_cast<uint64_t>(v.real_val) : v.aval);
  }
  ```
- Implemented untruncated `void*` foreign return value extraction:
  ```cpp
  if (dpi->return_type == "chandle") {
      void* ret_ptr = reinterpret_cast<void*(*)(uint64_t, ...)>(sym)(c_args[0], ...);
      return LogicVal::make_known(64, reinterpret_cast<uintptr_t>(ret_ptr));
  }
  ```
- All argument slots in the `reinterpret_cast` function pointer invocations (`void(*)()`, `void*(*)()`, `int64_t(*)()`, `int(*)()`) now pass full 64-bit registers.

### E. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`)
- Continuous Assignment Elaboration (`elaborator.cpp`):
  - Target check: Rejects `assign session_ptr = ...` with:
    `[CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment to chandle '...' is illegal per IEEE 1800-2023 section 35.5.4`
  - Expression check: Rejects bare `session_ptr` identifiers in continuous assignments with `[CAS-DTINPCIL]`, but permits equality checks (`==`, `!=`) against `null`.
- Persistent Monitor Execution (`evaluator.cpp`):
  - Rejects bare `chandle` identifiers in `$monitor` arguments with:
    `[CAS-DTINPCIL] Dynamic type in non-procedural context: chandle '...' used directly in $monitor per IEEE 1800-2023 section 35.5.4 & 21.2.3`
  - Allows `(session_ptr == null)` inside `$monitor` via binary equality filter.
