# Release v3.27.0.0: Net Aliasing, Bidirectional Net Unification, Multi-Net Driver Merging in Netlist Graph, Tri-state & 4-State Contention Resolution, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §10.6)

## 1. Overview & Milestone Scope
This release delivers **v3.27.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **59.8%** and implementing full IEEE Std 1800-2023 compliance for:
- **§10.6 (Net Aliasing)**:
  - **Syntax & Structural Declarations (§10.6)**:
    ```systemverilog
    alias net_lvalue = net_lvalue { = net_lvalue } ;
    ```
    - Creates bidirectional topological equivalence among two or more net lvalues.
    - Zero evaluation delay and zero delta cycles: aliased nets share a single underlying canonical NetID in the netlist graph.
  - **Bidirectional Net Unification via Disjoint Set Union (DSU)**:
    - Merges aliased nets into a unified equivalence class during elaboration.
    - Merges `inout` port connections directly into the canonical net equivalence class.
    - Canonical NetID remapping across `net_map`, `continuous_assigns`, `gates`, `slice_bindings`, `processes`, and `clocking_blocks`.
  - **Multi-Driver Merging & 4-State Wired Net Contention Resolution**:
    - All drivers attached to any of the aliased nets (continuous assignments, gate outputs, inout ports) are merged into the canonical NetID's driver set.
    - Active tri-state resolution (`'z'` does not interfere with active values).
    - 4-state contention resolution: conflicting active driver states (e.g. `8'hF0` vs `8'h0F`) resolve to `'x'` (`8'hxx`) per IEEE 1800-2023 Table 6-1.
  - **Context Diagnostics & Semantic Restriction (`[CAS-DTINPCIL]`)**:
    - Prohibits `alias` statements inside procedural scopes (`initial`, `always`, `task`, `function`):
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: 'alias' construct is not permitted in procedural context per IEEE 1800-2023 section 10.6
      ```
    - Prohibits `alias` statements inside program blocks:
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: 'alias' construct is not permitted in program scope per IEEE 1800-2023 section 24.3
      ```
    - Prohibits non-net variable operands (`reg`, `logic` declared as variable, `bit`, `int`):
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: alias operand is a variable, only nets are permitted per IEEE 1800-2023 section 10.6
      ```
    - Prohibits bit-width mismatches between aliased operands:
      ```text
      [CAS-DTINPCIL] Dynamic type in non-procedural context: bit width mismatch between aliased nets per IEEE 1800-2023 section 10.6
      ```

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexing & AST ([`lexer.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/lexer.hpp), [`lexer.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/lexer.cpp), [`ast_module.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/ast_module.hpp))
- Added `TokenType::TOKEN_ALIAS` keyword token in `lexer.hpp` and `lexer.cpp`.
- Added `AliasStatementNode` in `ast_module.hpp` representing alias declarations with chained operands (`aliased_exprs`, `declaring_file`, `declaring_line`).
- Added `std::vector<std::unique_ptr<AliasStatementNode>> aliases;` to `ModuleNode`.

### B. Frontend Parsing ([`parser_module.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_module.cpp), [`parser_stmt.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_stmt.cpp))
- In `parser_stmt.cpp`: Enforced diagnostic `[CAS-DTINPCIL]` if `alias` is encountered in procedural statements.
- In `parser_module.cpp`:
  - Added `parse_net_lvalue()` supporting simple identifiers, hierarchical dotted identifiers, bit-selects, and part-selects.
  - Parsed `TOKEN_ALIAS` in module and interface bodies, capturing chained assignments (`alias a = b = c;`) into `mod->aliases`.
  - Prohibited `alias` declarations within `program` blocks.

### C. Kernel Elaboration & DSU Net Unification ([`elaborator.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/kernel/elaborator.hpp), [`elaborator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/elaborator.cpp))
- In `Elaborator::elaborate_module`:
  - Checked operand types and bit-widths for all `mod->aliases`, throwing `[CAS-DTINPCIL]` for variable operands or width mismatches.
  - Collected full-net alias pairs and `inout` port connections into `alias_pairs`.
- In `Elaborator::elaborate`:
  - Executed Disjoint Set Union (DSU) across all `alias_pairs`.
  - Constructed `canonical_net_map` mapping each net ID to its canonical representative, and `alias_members` mapping each canonical ID to all aliased member nets.
  - Remapped all `net_map` symbol lookups, continuous assignment targets, gate outputs, slice bindings, process sensitivity targets, and clocking block signals to their canonical NetIDs.
  - Pruned redundant self-slice bindings.

### D. Multi-Driver Contention & State Synchronization ([`engine.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/engine.hpp), [`engine.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/engine.cpp), [`evaluator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/evaluator.cpp), [`scheduler.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp))
- In `Engine::load_elaboration`:
  - Populated `resolved_continuous_assigns`: drivers across aliased nets merge naturally under the unified canonical NetID key.
- In `Evaluator::write_slice` & `Evaluator::read_slice`:
  - Read and write slices through `canonical_net_map`.
  - Mirrored value updates to all members in `alias_members[canon_id]` to maintain transparent zero-delay synchronization for VCD dumps and external viewers.
- In `StratifiedScheduler::commit_nba_updates`:
  - Canonicalized target net IDs and synchronized alias members upon NBA commits.
