# Release v3.3.0.0: Associative Arrays, Dynamic Sparse Indexing, Built-in Methods, and Context Restrictions '[CAS-DTINPCIL]'

## 1. Overview & Milestone Scope
This release delivers **v3.3.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **26.1%** and implementing full IEEE Std 1800-2023 compliance for:
- **§7.8 (Associative Arrays)**:
  - Declarations of associative arrays with integral, vector, and string index types (`data_type array_name [ index_type ];`) (§7.8.1).
  - Dynamic sparse storage allocation where entries are allocated on-demand during procedural writes without contiguous memory reservations.
  - Safe 4-state unknown reading (§7.8.6): reading an uninitialized or non-existent key returns the default 4-state unknown value (`'x`, e.g. `32'hxxxxxxxx`) without adding the key to the array.
- **§7.8.4 (Built-in Associative Array Methods)**:
  - `.num()` / `.size()`: Returns total number of active entries currently allocated as a 32-bit integer.
  - `.exists(key)`: Returns `1'b1` if the given key exists in the array, `1'b0` otherwise, without allocating an entry.
  - `.first(ref key_var)`: Assigns to `key_var` the smallest index in the associative array; returns `1'b1` if found, `1'b0` if the array is empty.
  - `.last(ref key_var)`: Assigns to `key_var` the largest index in the associative array; returns `1'b1` if found, `1'b0` if the array is empty.
  - `.next(ref key_var)`: Finds the smallest index strictly greater than the given `key_var`, updates `key_var`, and returns `1'b1` (or `1'b0` if no such key exists).
  - `.prev(ref key_var)`: Finds the largest index strictly less than the given `key_var`, updates `key_var`, and returns `1'b1` (or `1'b0` if no such key exists).
  - `.delete(key)`: Deletes the element associated with the given key; no-op if key is absent.
  - `.delete()`: Removes all elements from the associative array, resetting entry count to 0.
- **Diagnostic [CAS-DTINPCIL] Enforcement**:
  - Enforced compilation/elaboration rule matching Synopsys VCS `Error-[DTINPCIL]`:
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment to associative array '...' is illegal per IEEE 1800-2023 section 7.8"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: associative array '...' used in continuous assignment per IEEE 1800-2023 section 7.8"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: associative array '...' used directly in $monitor per IEEE 1800-2023 section 7.8 & 21.2.3"`

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Associative Array Type Representation (`CAS/include/common/assoc_array_types.hpp`)
- `AssociativeArrayObject` encapsulates dynamic sparse associative storage using ordered search trees (`std::map`), providing logarithmic search/insert/erase times and exact lexicographical / ascending numeric key order required by IEEE Std 1800-2023:
  ```cpp
  struct AssociativeArrayObject {
      std::string name;
      uint32_t val_width = 32;
      bool is_signed = false;
      std::string key_type = "logic";
      uint32_t key_width = 32;
      bool is_string_key = false;

      std::map<uint64_t, LogicVal> elements;
      std::map<std::string, LogicVal> str_elements;

      uint32_t size() const;
      uint32_t num() const;
      bool exists(uint64_t key) const;
      bool first(uint64_t& out_key) const;
      bool last(uint64_t& out_key) const;
      bool next(uint64_t& in_out_key) const;
      bool prev(uint64_t& in_out_key) const;
      void delete_key(uint64_t key);
      void delete_all();
      LogicVal get(uint64_t key) const;
      void set(uint64_t key, const LogicVal& val);
  };
  ```

### B. AST & Parser Architecture (`CAS/include/frontend/`, `CAS/src/frontend/`)
- `PortNode` and `VarDeclStatementNode` extended with:
  - `bool is_associative_array = false;`
  - `std::string assoc_key_type = "";`
  - `uint32_t assoc_key_width = 32;`
- Dimension parsing recognizes index data types (`[logic [15:0]]`, `[int]`, `[string]`, `[bit [N:0]]`, `[*]`, typedefs) through `is_assoc_key_token()` and `parse_assoc_key_type()`.

### C. Elaboration & Diagnostic [CAS-DTINPCIL] Enforcement (`CAS/src/kernel/elaborator.cpp`)
- Module signals tagged with `is_associative_array` allocate an `AssociativeArrayObject` in `ElaborationResult::assoc_array_map`.
- Continuous assignments and continuous assignment expressions reject associative array identifiers, index selects, and method calls with diagnostic `[CAS-DTINPCIL]`.

### D. Kernel Execution & Evaluation (`CAS/src/kernel/evaluator.cpp`, `CAS/src/kernel/expr_evaluator.cpp`)
- `ExprEvaluator::eval` handles:
  - `IndexSelectNode`: Queries `assoc->get(key)`; returns default 4-state unknown `'x` if key does not exist.
  - `MethodCallNode`: Implements `.size()`, `.num()`, `.exists(key)`, `.first(key)`, `.last(key)`, `.next(key)`, `.prev(key)`, and `.delete(key)`. For traversal methods (`.first`, `.next`, etc.), the referenced variable argument is written in-place within the active execution frame or netlist.
- `Evaluator::execute_statement` handles:
  - `BlockingAssignNode`: Sparse element insertion and updates `assoc->set(key, rhs)`.
  - `TaskCallNode`: Method statements such as `sparse_mem.delete(key);` and `sparse_mem.delete();`.
  - `$monitor`: Validates expressions against `engine.is_assoc_array()`, raising `[CAS-DTINPCIL]` if an associative array appears directly or through index/method operations in persistent monitors.
