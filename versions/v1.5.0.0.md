# Release v1.5.0.0: Procedural Timing Controls, In-Body Events & Process Suspension

## 1. Overview & Milestone Scope
This release delivers **v1.5.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§9.4 (Procedural Timing Controls)**: In-body event synchronization (`@(posedge sig)`, `@(negedge sig)`, `@(sig)`), process suspension, and reactivation.
- **§9.4.1 (Delay Control)**: Delay-prefixed statements (`#d stmt;`).
- **§12.7.1 (Forever Loops)**: `forever` looping constructs with static anchor resumption (`loop_start_pc`).
- **Single Edge Execution Invariant**: Edge-triggered sequential processes trigger strictly once per physical clock transition across stratified delta loops.

---

## 2. Key Architecture Achievements & Refactorings

### A. Procedural Event Control & Process Suspension (§9.4.2)
- **`EventControlStatementNode`**:
  - Implemented parser and AST representations for procedural `@(...)` synchronization.
- **Non-Blocking Process Yielding**:
  - `BoundProcess` registers an `EventWaitTarget`. When an event control node is reached, the process flags `wait_target.active = true` and yields back to the scheduler without advancing `pc` to subsequent instructions.
- **Dynamic Reactivation**:
  - `StratifiedScheduler::resume_waiting_processes()` monitors net state transitions across the delta loop, clearing wait flags and reactivating suspended processes directly in the Active region upon edge detection.

### B. Statement-Prefixed Delays & Block Flattening
- **Composite Statement Parsing**:
  - Updated `Parser::parse_statement()` and `parse_statement_or_block()` to unpack `#d stmt;` into discrete delay and target nodes, ensuring sequential statements retain top-level scheduling semantics inside `bp.proc->body`.
- **`ForeverStatementNode` Anchoring**:
  - Added loop unrolling and `loop_start_pc` tracking, ensuring one-time setup statements (e.g. `clk = 0`) execute once while the loop body iterates indefinitely.

### C. Sequential Evaluation Guarding
- **`fired_in_time_slot` Guard**:
  - Introduced process-level fire guards reset at each discrete time slot, preventing multi-delta re-triggering of `always_ff` blocks during NBA stabilization while maintaining full sensitivity to combinatorial transitions.
