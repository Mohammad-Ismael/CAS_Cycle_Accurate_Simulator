# Release v3.31.0.0: Subroutine Formal Defaults, Named Argument Invocations (.name(expr)), Empty Positional Slots (, ,), Output/Inout Copy-Back, and Context Diagnostic '[CAS-DTINPCIL]' (IEEE Std 1800-2023 §13.5 & §13.6)

## 1. Overview & Milestone Scope
This release delivers **v3.31.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **65.4%** (`[██████████████████████████████████░░░░░░░░░░░░] 65.4%`) and implementing full IEEE Std 1800-2023 compliance for:
- **§13.5.3 (Subroutine Default Argument Values)**:
  - Task and function formal argument lists support default value expressions:
    ```systemverilog
    task automatic compute_next_slot(
        input  logic [31:0] base,
        input  int          offset = 16,
        input  int          multiplier = 2,
        input  logic [7:0]  tag = 8'hA0,
        output logic [31:0] res_addr,
        output logic [7:0]  res_tag
    );
    ```
  - Subroutine calls can omit any argument that has a defined default expression.
  - Evaluation of default expressions in the caller context when arguments are omitted.
- **§13.5.1 (Subroutine Named Argument Invocation)**:
  - Named argument syntax `.port_name(expression)` and `.port_name()` across all subroutine call sites (module tasks, functions, class methods, static methods, and constructors):
    ```systemverilog
    compute_next_slot(
        .base     (base_addr),
        .multiplier(4),
        .res_addr (tmp_addr),
        .res_tag  (tmp_tag)
        // offset takes default 16, tag takes default 8'hA0
    );
    ```
  - Named arguments can be provided in any arbitrary order.
  - Positional arguments can precede named arguments, but once an argument is passed by name, all subsequent arguments must be passed by name per IEEE Std 1800-2023 §13.5.1.
  - Omission of named argument expression (`.port_name()`) evaluates the formal default value.
- **§13.5.3 (Empty Positional Argument Slots)**:
  - Empty positional slots delimited by commas (`func(arg1, , arg3)`):
    ```systemverilog
    res = pack_metrics(2, , 3); // latency=2, burst takes default 4, qos=3
    ```
  - Leading empty slots (`(, b, c)`), middle empty slots (`(a, , c)`), multiple consecutive empty slots (`(a, , , d)`), and trailing empty slots (`(a, b, )`).
  - Calls with zero arguments (`pack_metrics()`) resolving all formal defaults.
- **Subroutine Output & Inout Binding Copy-Back**:
  - Out-of-order named argument binding of `output` and `inout` arguments (`.res_addr(tmp_addr)`).
  - Robust copy-back upon subroutine termination across process frames, task activation frames, execution context local variable frames, class object properties, and netlist signals.
- **Context Diagnostics & Semantic Restrictions (`[CAS-DTINPCIL]`)**:
  - Enforced IEEE Std 1800-2023 §13.5.1:
    - Positional argument following named argument:
      ```text
      [CAS-DTINPCIL] Positional argument cannot follow named argument in subroutine call per IEEE 1800-2023 section 13.5.1
      ```
    - Unrecognized formal argument name in named argument call:
      ```text
      [CAS-DTINPCIL] Unrecognized formal argument name '<name>' in subroutine call per IEEE 1800-2023 section 13.5.1
      ```
    - Duplicate binding for same formal argument:
      ```text
      [CAS-DTINPCIL] Duplicate binding for formal argument '<name>' in subroutine call per IEEE 1800-2023 section 13.5.1
      ```
    - Missing mandatory formal argument without default:
      ```text
      [CAS-DTINPCIL] Missing mandatory subroutine argument '<name>' without default value in subroutine call per IEEE 1800-2023 section 13.5.3
      ```

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend AST Extensions ([`ast_stmt.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/ast_stmt.hpp), [`ast_expr.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/ast_expr.hpp), [`parser.hpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/include/frontend/parser.hpp))
- Extended `TaskCallNode` with `std::vector<std::string> arg_names;`.
- Extended `FunctionCallNode`, `MethodCallNode`, `StaticMethodCallNode`, and `ClassNewNode` with `std::vector<std::string> arg_names;`.
- Maintained exact AST compatibility: positional arguments store empty strings in `arg_names`, and empty argument slots store `nullptr` pointers in `args`.
- Added `struct ParsedCallArgs { std::vector<std::unique_ptr<ExpressionNode>> args; std::vector<std::string> arg_names; };` to `parser.hpp`.

### B. Unified Call Argument Parsing ([`parser_stmt.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_stmt.cpp), [`parser_expr.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/frontend/parser_expr.cpp))
- Implemented `Parser::parse_call_argument_list()`:
  - Tracks whether a named argument has been parsed (`seen_named`).
  - Detects `.port_name( [expr] )` and records formal identifier with expression or `nullptr`.
  - Detects empty positional slots via consecutive commas (`TOKEN_COMMA`), leading commas, and trailing commas before `TOKEN_RPAREN`.
  - Enforces `[CAS-DTINPCIL]` if any positional expression or empty slot appears after `seen_named == true`.
- Integrated `parse_call_argument_list()` across:
  - Task statements (`ident(...)`, `super.task(...)`, `this.task(...)`, `Class::task(...)`).
  - Function call expressions (`func(...)`).
  - Method calls (`obj.method(...)`, `this.method(...)`, `super.method(...)`).
  - Static method calls (`Class::method(...)`).
  - Constructor calls (`new(...)`).

### C. Kernel Task & Function Argument Binding Engine ([`scheduler.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/scheduler.cpp), [`evaluator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/evaluator.cpp), [`expr_evaluator.cpp`](file:///i:/CAS_Cycle_Accurate_Simulator/CAS/src/kernel/expr_evaluator.cpp))
- Implemented 3-pass argument mapping across all routine invocations:
  1. Positional mapping: binds actuals `0..N-1` to formals `0..N-1`. Checks bounds against `formals.size()`.
  2. Named mapping: resolves `.name` against formal list, detects duplicate bindings, flags unrecognized formal names with `[CAS-DTINPCIL]`.
  3. Default & mandatory resolution: for each formal, verifies if explicitly passed with an expression; if empty slot or omitted, evaluates `formal.default_value`; if no default value exists, throws `[CAS-DTINPCIL]` for missing mandatory argument.
- Output & inout binding copy-back:
  - Correctly records destination variable identifier regardless of whether passed positionally or by name.
  - In `StratifiedScheduler::write_task_output` and procedural task execution in `Evaluator`, checks:
    - Caller task frame (`caller_frame.local_frame`)
    - Process execution context active local frames (`expr_eval.get_context().lookup_local`)
    - Class instance properties (`current_this->set_property`)
    - Netlist signals (`engine.netlist`)
