# Release v3.11.0.0: SystemVerilog Assertions (SVA) Sequence Repetition Operators ([*N], [*min:max], [=N], [->N]), Multi-Thread Sequence State Tracking, and Context Diagnostic '[CAS-DTINPCIL]'

## 1. Overview & Milestone Scope
This release delivers **v3.11.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **37.4%** and implementing full IEEE Std 1800-2023 compliance for:
- **§16.9.2 (SVA Sequence Repetition Operators)**:
  - **Consecutive Repetition `expr [* count]` and `expr [* min_count : max_count]` (§16.9.2.1)**: Requires `expr` to match on consecutive clock ticks for exactly `count` cycles (or within `[min_count : max_count]` cycles).
  - **Non-Consecutive Repetition `expr [= count]` (§16.9.2.2)**: Requires `expr` to match `count` times interspersed with arbitrary non-matching cycles, with empty or non-matching cycles allowed after the final match before the next sequence step.
  - **Goto Repetition `expr [-> count]` (§16.9.2.3)**: Requires `expr` to match `count` times interspersed with arbitrary non-matching cycles, with the sequence completing on the exact clock cycle the final match occurs.
  - **Sequence Concatenation & Delays `##N` (§16.9.1)**: Supports cycle-delay concatenation connecting repetitions and sequence expressions (e.g. `(busy [*3] ##1 done)`).
- **Multi-Thread Sequence State Tracking (§16.7, §16.14 & §4.4)**:
  - Evaluates antecedent and consequent sequence state across multiple active assertion threads (`SvaThread`) in the Observed scheduler region.
  - Manages remaining cycle delays, repetition counters, and match criteria dynamically before triggering action blocks in the Reactive scheduler region.
- **Associative Array Token Disambiguation (§7.8.1 vs §16.9.2)**:
  - Disambiguates `[*` in associative array wildcard declarations (`int arr[*];`) from sequence repetition operators.
- **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
  - Strictly rejects SVA sequence repetition operators in continuous assignments (`assign`), procedural assignments, and `$monitor` arguments with diagnostic `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend Lexer & AST Nodes (`CAS/include/frontend/lexer.hpp`, `CAS/src/frontend/lexer.cpp`, `CAS/include/frontend/ast_expr.hpp`)
- Added lexer tokens: `TOKEN_REP_CONSEC` (`[*`), `TOKEN_REP_NON_CONSEC` (`[=`), and `TOKEN_REP_GOTO` (`[->`).
- Defined `RepetitionType` enum: `CONSECUTIVE`, `NON_CONSECUTIVE`, `GOTO`.
- Defined AST nodes:
  - `SequenceRepetitionNode`: Represents `expr [* count]`, `expr [= count]`, or `expr [-> count]`, tracking `RepetitionType`, `min_count`, and `max_count`.
  - `SequenceConcatItem`: Represents a sequence step with an associated cycle delay (`uint32_t delay`, `std::unique_ptr<ExpressionNode> expr`).
  - `SequenceConcatNode`: Represents concatenated sequence expressions `expr ##delay expr ##delay ...`.

### B. Parser Enhancements (`CAS/include/frontend/parser.hpp`, `CAS/src/frontend/parser_expr.cpp`, `CAS/src/frontend/parser_module.cpp`, `CAS/src/frontend/parser_stmt.cpp`)
- Implemented `Parser::parse_sequence_element()` to parse expressions and attach repetition operators.
- Implemented `Parser::parse_sequence_expression()` to parse cycle delays (`##N`) and construct `SequenceConcatNode`.
- Updated `Parser::parse_primary()` to route parenthesized expressions in sequences/properties to `parse_sequence_expression()`.
- Updated `parse_property()`, `parse_sequence()`, and inline `assert property` statements.
- Preserved associative array wildcard syntax (`int arr[*];`) in both module signal and procedural variable parsers by recognizing `TOKEN_REP_CONSEC` followed by `TOKEN_RBRACKET`.

### C. Kernel Sequence Flattening & Multi-Thread Tracking (`CAS/include/common/sva_types.hpp`, `CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/scheduler.cpp`)
- Defined `SvaSequenceStep`:
  ```cpp
  struct SvaSequenceStep {
      uint32_t cycle_delay = 1;
      std::unique_ptr<ExpressionNode> expr = nullptr;
      RepetitionType rep_type = RepetitionType::CONSECUTIVE;
      uint32_t min_count = 1;
      uint32_t max_count = 1;
  };
  ```
- Implemented `extract_sequence_steps()` in elaboration to flatten recursive sequence expressions and repetition nodes into sequential steps.
- Updated `SvaThread` with state tracking fields:
  ```cpp
  uint32_t remaining_delay = 0;
  size_t step_index = 0;
  uint32_t current_rep_count = 0;
  uint32_t target_rep_count = 1;
  RepetitionType rep_type = RepetitionType::CONSECUTIVE;
  ```
- Enhanced `StratifiedScheduler::evaluate_sva_assertions()` state machine:
  - Advances cycle delays decrementally on each clock event.
  - Evaluates repetition match conditions:
    - `CONSECUTIVE`: Increments `current_rep_count` on match; fails thread immediately on non-match if `current_rep_count < min_count`. Advances to next step upon reaching target count.
    - `GOTO`: Stays pending on non-matching cycles without failing; matches sequence on the exact cycle the target count is satisfied.
    - `NON_CONSECUTIVE`: Increments count on match while allowing non-matching cycles.
  - Commits passing assertions to the Reactive region pass queue and invokes success action blocks.

### D. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`, `CAS/src/kernel/expr_evaluator.cpp`)
- Rejects repetition operators in continuous assignments during elaboration:
  `[CAS-DTINPCIL] SVA sequence repetition operator used outside sequence/property context in continuous assignment per IEEE 1800-2023 section 16.9.2`
- Rejects repetition operators in procedural expressions and `$monitor`:
  `[CAS-DTINPCIL] SVA sequence repetition operator used outside sequence/property context per IEEE 1800-2023 section 16.9.2`
