# Release v2.1.0.0: Automatic Functions, Re-entrant Tasks, and Dynamic Call Frames

## 1. Overview & Milestone Scope
This release delivers **v2.1.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§13.4.2 (Automatic Functions & Recursive Subroutines)**:
  - Keyword and grammar support for `function automatic ...` and `function static ...`.
  - Dynamic activation frame (`CallFrame` / `ScopeFrame`) allocation per invocation: each function invocation dynamically allocates independent storage for formal argument inputs, local variable declarations, and return value.
  - Full recursion support: recursive calls (direct and indirect) maintain isolated execution state across recursion levels without overwriting caller stack frames.
  - Implicit return variable allocation named after the function with dynamic frame scoping.
- **§13.5.1 (Automatic Tasks & Concurrent Re-entrant Execution)**:
  - Keyword and grammar support for `task automatic ...` and `task static ...` with ANSI and non-ANSI port lists (`input`, `output`, `inout`).
  - Dynamic call frame allocation per task instance: concurrent processes calling the same shared task allocate distinct activation frames (`TaskActivationFrame`).
  - Suspension & resumption across stratified scheduler wait intervals: procedural delays (`#delay`) and event controls (`@(event)`) inside task instances preserve each invocation's call stack frame and local variables across suspension.
  - Caller argument write-back: output arguments are safely committed back to caller targets upon task completion.
- **§10.6 & §19.7 (Expression-Based Delays)**:
  - Extended procedural delay controls (`#delay`) to evaluate expressions and identifiers (e.g., `#delay_ticks;` or `#(expr);`) dynamically within the caller or task activation frame.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Lifetime & Activation Frames (§13.4.2 & §13.5)
- Under IEEE Std 1800-2023, subroutines declared with the `automatic` lifetime allocate all local variables, formal arguments, and return values dynamically upon invocation.
- Each call pushes a new activation frame (`ScopeFrame`) containing private storage for all formal inputs/outputs and local variables.
- Upon subroutine exit, output arguments are written back to the caller's target variables and the activation frame is destroyed.

### B. Recursive Function Execution (§13.4.2)
- Functions declared `automatic` can call themselves directly or mutually.
- Intermediate evaluation states (such as local variables `logic [31:0] temp;` and the implicit function return variable) remain private to each recursive call level.
- High-level recursion depth protection prevents stack overflow during indeterminate simulation transitions.

### C. Re-entrant Concurrent Tasks (§13.5.1)
- Multiple concurrent processes (e.g., distinct `initial` blocks or `fork-join` threads) calling the same `task automatic` execute concurrently without shared state interference.
- Local variables and arguments inside the task remain completely isolated between processes.
- Timing controls (`#delay`, `@event`) within a task suspend the specific calling process. The task's invocation frame and PC are saved on that process's call stack (`BoundProcess::call_stack`) and cleanly restored when awakened by the scheduler time wheel.

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & AST Grammar
- **Tokens (`lexer.hpp`, `lexer.cpp`)**:
  - Added `TOKEN_STATIC` (`static`) to `TokenType` alongside `TOKEN_AUTOMATIC` (`automatic`).
- **AST Nodes (`ast_module.hpp`, `ast_stmt.hpp`)**:
  - `TaskNode`: Added `std::string scope;`, `bool is_automatic;`, and `std::vector<PortNode> ports;`.
  - `FunctionNode`: Added `std::string scope;` and `bool is_automatic;`.
  - `TaskCallNode`: Extended to support argument expression lists `std::vector<std::unique_ptr<ExpressionNode>> args;`.
  - `DelayStatementNode`: Extended to support dynamic expression delays `std::unique_ptr<ExpressionNode> delay_expr;`.

### B. Subroutine Parsing (`parser_task.cpp`, `parser_function.cpp`, `parser_stmt.cpp`)
- Added dedicated `Parser::parse_task()` modular implementation supporting ANSI port declarations (`input`, `output`, `inout`), data types (`integer`, `logic`, `wire`, `reg`), and local declarations before the task body.
- Updated `Parser::parse_function()` to tag `is_automatic` based on `automatic` / `static` keywords.
- Extended procedural delay parsing to handle identifiers and expressions following `#`.
- Extended task call statement parsing to parse comma-separated arguments: `task_name(arg1, arg2, ...);`.

### C. Dynamic Call Stack & Execution Context (`execution_context.hpp`, `elaborator.hpp`, `evaluator.cpp`, `expr_evaluator.cpp`)
- **Activation Frames (`elaborator.hpp`)**:
  - Defined `TaskActivationFrame` holding the active `TaskNode*`, flattened statement stream, `local_frame` symbol table, and caller `output_bindings`.
  - Embedded `std::vector<TaskActivationFrame> call_stack` within each `BoundProcess`.
- **Expression Evaluation & Scoping (`expr_evaluator.cpp`, `evaluator.cpp`)**:
  - Variable lookups and assignments search the function's `ExecutionContext` call stack first, then the active process's `TaskActivationFrame`, before falling back to module netlist signals.
  - Added recursion guard to prevent indefinite recursion on uninitialized logic vectors (`x`).

### D. Stratified Scheduler Task Execution Pipeline (`scheduler.hpp`, `scheduler.cpp`)
- Implemented task invocation (`StratifiedScheduler::invoke_task`) and output write-back (`StratifiedScheduler::write_task_output`).
- `StratifiedScheduler::step_process` executes across active task call frames:
  - Timing controls (`#delay`, `@event`) within a task suspend the process cleanly, scheduling wakeup on the `TimeWheel`.
  - Upon task completion, output arguments commit to caller targets and the frame pops from `bp.call_stack`.
