# Release v3.4.0.0: Object-Oriented Programming Classes, Handles, Constructors 'new', Member Properties, Methods, and Context Diagnostic '[CAS-DTINPCIL]'

## 1. Overview & Milestone Scope
This release delivers **v3.4.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **27.5%** and implementing full IEEE Std 1800-2023 compliance for:
- **§8 (Object-Oriented Programming Classes)**:
  - Class declarations (`class class_identifier; ... endclass [: class_identifier]`) encapsulating member properties, constructors, and member methods (§8.3).
  - Object handle declarations (`class_identifier handle_name;`) initialized to `null` (zero handle identifier) (§8.4).
  - Constructors (`function new(...)`) with optional argument lists and default parameter expressions (§8.7, §8.8).
  - Object instantiation via `handle = new(...)` allocating a discrete heap-backed `ClassObject` instance with unique object identity.
  - Member property procedural access and modification (`pkt.prop = val`, `this.prop = val`) (§8.4).
  - Member subroutine invocation: functions returning values (`chksum = pkt.calc_checksum()`) and tasks executing procedural statements (`pkt.update_payload(...)`) (§8.5).
  - `this` self-reference keyword for disambiguating class property access (§8.11).
  - `null` handle literal and equality comparisons (`handle == null`, `handle !== null`) (§8.4).
  - Return statements (`return expr;` and `return;`) inside subroutines per IEEE Std 1800-2023 §13.4.1.
- **Diagnostic [CAS-DTINPCIL] Enforcement**:
  - Enforced compilation, elaboration, and runtime diagnostics matching Synopsys VCS `Error-[DTINPCIL]`:
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment to class handle '...' is illegal per IEEE 1800-2023 section 8.4"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: class handle '...' used in continuous assignment per IEEE 1800-2023 section 8.4"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: class property '...' used in continuous assignment per IEEE 1800-2023 section 8.4"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: class method '...' used in continuous assignment per IEEE 1800-2023 section 8.5"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: class handle '...' used directly in $monitor per IEEE 1800-2023 section 8.4 & 21.2.3"`
    `"[CAS-DTINPCIL] Dynamic type in non-procedural context: class property '...' used in $monitor per IEEE 1800-2023 section 8.4 & 21.2.3"`

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Class Object Storage & Identity (`CAS/include/common/class_types.hpp`)
- `ClassObject` represents a live class instance allocated on the simulation kernel heap:
  ```cpp
  struct ClassObject {
      uint64_t handle_id = 0;
      std::string class_type_name;
      const ClassNode* class_def = nullptr;
      std::unordered_map<std::string, LogicVal> properties;

      bool has_property(const std::string& name) const;
      LogicVal get_property(const std::string& name) const;
      void set_property(const std::string& name, const LogicVal& val);
  };
  ```
- Object handles are 64-bit scalar values where `0` represents the uninstantiated `null` handle, and values `> 0` index allocated instances in `Engine::heap`.

### B. AST & Parser Architecture (`CAS/include/frontend/`, `CAS/src/frontend/`)
- `ClassNode` and `ClassMemberVar` capture class member declarations, function subroutines, task subroutines, and constructor `new`.
- `NullNode`, `ThisNode`, `ClassNewNode` represent the `null` literal, `this` self-reference, and `new(...)` constructor expressions.
- `ReturnStatementNode` represents procedural `return expr;` statements.
- `Parser::parse_class()` parses compilation-unit and module-level class declarations.
- `Parser::parse_function()` and `Parser::parse_task()` updated to support parameter default values, optional `input` direction, and `new` constructor syntax.

### C. Elaboration & Diagnostic [CAS-DTINPCIL] Enforcement (`CAS/src/kernel/elaborator.cpp`)
- Module signals and ports tagged with `is_class_handle` allocate 64-bit netlist storage initialized to `null` (`LogicVal(64, 0, 0)`).
- Continuous assignments and continuous assignment expressions reject class handle identifiers, member accesses, method calls, `null`, `new`, and `this` with diagnostic `[CAS-DTINPCIL]`.

### D. Kernel Execution & Evaluation (`CAS/src/kernel/evaluator.cpp`, `CAS/src/kernel/expr_evaluator.cpp`)
- `ExprEvaluator::eval` handles:
  - `NullNode`: Evaluates to `LogicVal(64, 0, 0)`.
  - `ThisNode`: Evaluates to `LogicVal(64, current_this->handle_id, 0)`.
  - `ClassNewNode`: Allocates object on heap, initializes properties, executes constructor `new(...)`, and returns handle.
  - `MemberAccessNode`: Resolves `this.prop` or `handle.prop` from `ClassObject::properties`.
  - `MethodCallNode`: Executes class functions with `current_this` bound to the object instance.
  - `IdentifierNode`: Transparently resolves member properties when executing within a class method context (`current_this`).
  - Binary comparisons (`==`, `!=`, `===`, `!==`): Correctly evaluates null checks (`pkt == null`).
- `Evaluator::execute_statement` handles:
  - `BlockingAssignNode`:
    - Constructor assignments (`pkt = new(...)`) allocating heap objects and writing handle IDs.
    - Member property assignments (`pkt.cmd = ...` and `this.cmd = ...`).
  - `TaskCallNode`: Dispatches class member task calls (`pkt.update_payload(...)`) with `current_this` bound to the targeted instance.
  - `ReturnStatementNode`: Assigns return value to the active function frame and sets `returned = true`.
  - `$monitor`: Validates expressions against `engine.is_class_handle()`, raising `[CAS-DTINPCIL]` if class handles or properties appear in persistent monitors.
