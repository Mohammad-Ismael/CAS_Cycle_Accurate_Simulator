# Release v2.2.0.0: Parallel Blocks (fork ... join, join_any, join_none)

## 1. Overview & Milestone Scope
This release delivers **v2.2.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§9.3.2 (Parallel Blocks: `fork ... join`, `join_any`, `join_none`)**:
  - Keyword and grammar support for `fork`, `join`, `join_any`, and `join_none` statements with optional block labels (`fork : label_name ... join : label_name`) and optional trailing semicolons.
  - Dynamic parallel process instantiation: each statement or block enclosed within a `fork` block spawns as an independent child thread (`BoundProcess`) inheriting lexical scope, parent process attributes, and task activation frame context.
  - Complete join barrier semantics:
    * `fork ... join`: Parent process blocks until **all** child threads complete execution.
    * `fork ... join_any`: Parent process blocks until **any** single child thread completes execution; remaining threads continue concurrent execution in the background.
    * `fork ... join_none`: Parent process does **not** block; it continues execution in the current simulation cycle concurrently with all spawned child threads.
  - Full support for nested timing controls (`#delay`, `@(event)`), task invocations, and nested fork blocks within parallel threads.
  - Stratified event scheduling: spawned child threads and unblocked parent processes are scheduled strictly in accordance with IEEE 1800-2023 §4 Active and Postponed regions.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Parallel Block Execution (§9.3.2)
- Under IEEE Std 1800-2023 §9.3.2, a `fork ... join/join_any/join_none` block executes statements in parallel threads rather than sequentially.
- When an executing process reaches a `fork` construct:
  1. The construct creates a separate concurrent process for each branch enclosed in the block.
  2. Each branch begins executing in the Active region of the current simulation time slot.
  3. The parent process's progression depends on the specified join keyword:
     - **`join`**: Suspends the parent process until all spawned child processes have terminated.
     - **`join_any`**: Suspends the parent process until any single child process terminates. Any remaining un-terminated children continue running concurrently in the background.
     - **`join_none`**: The parent process does not suspend at all; it continues execution immediately in the current time slot.

### B. Thread Tree & Scope Inheritance
- Spawned child processes maintain a bidirectional reference hierarchy (`parent_pid` and `child_pids`).
- Child threads inherit:
  - Lexical scope (`bp.scope`).
  - Active task call stack (`bp.call_stack`), granting seamless access to local variables and arguments of enclosing automatic routines (§13.4, §13.5).
  - Module netlist mapping.
- Each child thread maintains independent instruction counters (`pc`), dynamic statement streams (`dynamic_statements`), delay states (`is_delayed`), and event wait targets (`wait_target`).

### C. Stratified Scheduler Synchronization
- Process barriers (`ForkBarrier`) track barrier configuration (`JoinType`), child count (`total_children`), and termination progress (`completed_children`).
- When a child process terminates:
  - It notifies its parent via `notify_parent_child_completed(child_pid)`.
  - If the barrier condition is satisfied (`completed == total` for `join`, `completed >= 1` for `join_any`), the barrier is marked inactive and the parent process is awakened in the Active region.
  - If a remaining child terminates in the background after a `join_any` barrier has already unblocked, notification returns harmlessly without disturbing subsequent parent delays or operations.

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & AST Grammar
- **Tokens (`lexer.hpp`, `lexer.cpp`)**:
  - Added `TOKEN_FORK` (`fork`), `TOKEN_JOIN` (`join`), `TOKEN_JOIN_ANY` (`join_any`), and `TOKEN_JOIN_NONE` (`join_none`) to `TokenType`.
  - Added keyword mappings in `Lexer::tokenize()`.
- **AST Nodes (`ast_stmt.hpp`)**:
  - Defined `enum class JoinType { JOIN, JOIN_ANY, JOIN_NONE };`.
  - Created `ForkStatementNode` inheriting from `StatementNode`:
    ```cpp
    struct ForkStatementNode : public StatementNode {
        std::string block_name;
        JoinType join_type = JoinType::JOIN;
        std::vector<std::unique_ptr<StatementNode>> branches;
        ...
    };
    ```
- **Parser (`parser_stmt.cpp`)**:
  - Implemented `parse_statement()` handler for `TOKEN_FORK`.
  - Enclosed branch statements parsed until matching `join`, `join_any`, or `join_none` token.
  - Supported optional block labels (`fork : name ... join : name`) and trailing semicolons.

### B. Kernel Elaborator & Process Data Structures (`elaborator.hpp`)
- **Barrier Model**:
  ```cpp
  struct ForkBarrier {
      bool active = false;
      bool in_fork_setup = false;
      JoinType join_type = JoinType::JOIN;
      size_t total_children = 0;
      size_t completed_children = 0;
      std::vector<size_t> child_pids;
  };
  ```
- **BoundProcess Extensions**:
  - `size_t parent_pid = (size_t)-1;`
  - `ForkBarrier fork_barrier;`
  - `std::vector<StatementNode*> dynamic_statements;`
  - `bool is_delayed = false;`

### C. Stratified Scheduler Execution Engine (`scheduler.hpp`, `scheduler.cpp`)
- **Fork Invocation (`StratifiedScheduler::invoke_fork`)**:
  - Spawns child `BoundProcess` threads from AST branch nodes.
  - Unwraps enclosed blocks using `flatten_task_statements` into flat sequential statement streams.
  - Steps child threads into the Active region.
- **Child Completion (`StratifiedScheduler::notify_parent_child_completed`)**:
  - Evaluates barrier unblock conditions (`JOIN` vs `JOIN_ANY`).
  - Awaken parent process directly into the Active event region upon satisfaction.
- **Scheduler Process Step (`StratifiedScheduler::step_process`)**:
  - Enhanced to execute child threads (`dynamic_statements`) with full support for timing delays (`#delay`), event controls (`@(edge)`), sub-task calls, nested forks, and intra-assignment timing.
  - Barrier check prevents parent from stepping while waiting for child threads.
  - Memory-safe indexing protects against vector reallocation during dynamic thread spawning.
- **Root Process Initialization Guard (`StratifiedScheduler::run_simulation`)**:
  - T=0 root process loop bounds iteration strictly to root processes (`parent_pid == (size_t)-1`), preventing premature execution of spawned child threads before their scheduled times.
