# Release v3.15.0.0: Direct Programming Interface (DPI-C: Open Arrays '[]', Formal Open Array Handles 'const svOpenArrayHandle', Standard Inquiry & Access APIs 'svSize' and 'svGetArrElemPtr1', and Context Diagnostic '[CAS-DTINPCIL]')

## 1. Overview & Milestone Scope
This release delivers **v3.15.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **43.0%** and implementing full IEEE Std 1800-2023 compliance for:
- **§35.5.6.1 & Annex I.9 (DPI-C Open Arrays & Foreign Inquiry/Access C APIs)**:
  - **Open Array Formal Declarations**:
    - Unsized bracket syntax `[]` on formal arguments of DPI-C import declarations (`import "DPI-C" function int c_sum_open_array(input int arr[]);`).
    - Accommodates actual arrays of arbitrary lengths and dimension bounds without requiring specialized compile-time wrappers.
  - **Formal Open Array Handle Representation**:
    - Pass arrays by reference as opaque handles `const svOpenArrayHandle` (`typedef void* svOpenArrayHandle;`).
    - Preserves canonical 0-based array index normalization per IEEE 1800-2023 Annex I.9.2.
  - **Standard Annex I.9 Inquiry & Element Access Global C APIs**:
    - Global symbol export with `-rdynamic` for shared object interoperability:
      - `int svSize(const svOpenArrayHandle h, int d)`: Queries size of dimension `d` (returns canonical element count).
      - `int svLength(const svOpenArrayHandle h, int d)`: Alias for `svSize`.
      - `int svDimensions(const svOpenArrayHandle h)`: Returns dimension count (`1`).
      - `int svLeft(const svOpenArrayHandle h, int d)`: Returns left index (`0`).
      - `int svRight(const svOpenArrayHandle h, int d)`: Returns right index (`size - 1`).
      - `int svLow(const svOpenArrayHandle h, int d)`: Returns low bound (`0`).
      - `int svHigh(const svOpenArrayHandle h, int d)`: Returns high bound (`size - 1`).
      - `int svIncrement(const svOpenArrayHandle h, int d)`: Returns increment direction (`1`).
      - `int svSizeOfArray(const svOpenArrayHandle h)`: Returns array size.
      - `void* svGetArrElemPtr1(const svOpenArrayHandle h, int indx)`: Returns direct pointer to array element at canonical 0-based index `indx`.
      - `void* svGetArrElemPtr2(const svOpenArrayHandle h, int indx1, int indx2)`: Multidimensional element pointer retrieval.
      - `void* svGetArrElemPtr3(const svOpenArrayHandle h, int indx1, int indx2, int indx3)`: 3D element pointer retrieval.
      - `void* svGetArrElemPtr(const svOpenArrayHandle h, int indx1, ...)`: Variadic element pointer retrieval.
      - `void* svGetArrayPtr(const svOpenArrayHandle h)`: Direct pointer to start of contiguous array elements.
  - **Actual Array Storage Marshalling & Inout Writeback**:
    - Seamlessly extracts elements from unpacked memories (`MemoryArray`), dynamic arrays (`DynamicArrayObject`), and queues (`QueueObject`).
    - Supports `input`, `output`, and `inout` open array arguments with post-invocation state synchronization and writeback.
  - **Context Diagnostic Enforcement (`[CAS-DTINPCIL]`)**:
    - Rejects open array handles and unpacked arrays appearing directly in continuous assignments (`assign`) during elaboration with `[CAS-DTINPCIL]`.
    - Rejects continuous assignments driving open array variables with `[CAS-DTINPCIL]`.
    - Rejects open array handles and unpacked arrays in persistent `$monitor` argument lists outside explicit element index dereferences with `[CAS-DTINPCIL]`.

## 2. Technical Architecture & Implementation Mechanics

### A. Frontend AST Nodes & Lexer (`CAS/include/frontend/ast_module.hpp`)
- Extended `PortNode`:
  - Added `bool is_open_array = false;` to represent open array formal parameters in DPI subroutine headers.

### B. Parser Enhancements (`CAS/src/frontend/parser_module.cpp`)
- DPI-C Import Parsing (`parse_dpi_import`):
  - Detected unsized brackets `[]` before and after the port identifier:
    ```cpp
    bool is_open_array = false;
    if (match(TokenType::TOKEN_LBRACKET)) {
        if (match(TokenType::TOKEN_RBRACKET)) {
            is_open_array = true;
        } else { ... }
    }
    std::string pname = current.text;
    expect(TokenType::TOKEN_IDENTIFIER, "Expected port identifier in DPI import");
    if (match(TokenType::TOKEN_LBRACKET)) {
        if (match(TokenType::TOKEN_RBRACKET)) {
            is_open_array = true;
        } else { ... }
    }
    port.is_open_array = is_open_array;
    ```

### C. Kernel Architecture & DPI-C Handle Registry (`CAS/include/common/dpic_types.hpp`, `CAS/src/engine.cpp`)
- Defined canonical open array handle and layout in `CAS/include/common/dpic_types.hpp`:
  ```cpp
  typedef void* svOpenArrayHandle;

  struct SvOpenArray {
      int size = 0;
      int elem_width = 32;
      std::vector<int32_t> int32_elements;
      std::vector<int64_t> int64_elements;
      MemoryArray* source_mem = nullptr;
      DynamicArrayObject* source_dyn = nullptr;
  };
  ```
- Implemented global `extern "C"` standard inquiry and element access APIs in `CAS/src/engine.cpp` exported with `-rdynamic`.

### D. DPI-C Argument Marshalling & Invocation (`CAS/src/kernel/expr_evaluator.cpp`)
- In `ExprEvaluator::eval(FunctionCallNode* ...)`:
  - Detected DPI import calls prior to scalar argument evaluation, passing expression AST nodes directly to `eval_dpi_call(dpi, fn_call->args, scope)`.
- In `ExprEvaluator::eval_dpi_call`:
  - Checked `dpi->tf_ports[i].is_open_array`.
  - When true, extracted the referenced array name, located the underlying storage across `memory_map`, `dynamic_array_map`, or local activation frames, constructed an `SvOpenArray` descriptor with normalized 0-based ordering, and passed `reinterpret_cast<uint64_t>(oa.get())` to foreign code.
  - After foreign execution, performed automatic writeback for `output` and `inout` open array arguments.

### E. Diagnostic Enforcement (`CAS/src/kernel/elaborator.cpp`, `CAS/src/kernel/evaluator.cpp`)
- Continuous Assignment Elaboration (`elaborator.cpp`):
  - Target check: Rejects `assign arr = ...` with:
    `[CAS-DTINPCIL] Dynamic type in non-procedural context: continuous assignment to open array or unpacked array 'arr' is illegal per IEEE 1800-2023 section 35.5.6.1`
  - Expression check: Rejects bare `arr` identifiers without index dereference in continuous assignments with `[CAS-DTINPCIL]`.
- Persistent Monitor Execution (`evaluator.cpp`):
  - Rejects bare open array handles and unpacked arrays in `$monitor` arguments without index select with:
    `[CAS-DTINPCIL] Dynamic type in non-procedural context: open array handle or unpacked array 'arr' used directly in $monitor per IEEE 1800-2023 section 35.5.6.1 & 21.2.3`
