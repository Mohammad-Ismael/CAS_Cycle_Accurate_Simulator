# Release v3.5.0.0: OOP Class Inheritance 'extends', 'super.new' Constructor Chaining, Virtual Methods & Dynamic Polymorphic Dispatch, and '$cast' Dynamic Downcasting

## 1. Overview & Milestone Scope
This release delivers **v3.5.0.0** of the Cycle Accurate Simulator (CAS), advancing simulator maturity to **28.9%** and implementing full IEEE Std 1800-2023 compliance for:
- **§8.13 (Inheritance & Subclassing via 'extends')**:
  - Subclass declarations (`class derived_class extends base_class; ... endclass`).
  - Derived class instances inherit all member properties, tasks, and functions from the base class.
  - Linear and hierarchical class inheritance trees with cycle detection and base class validation.
  - Multi-level property aggregation initializing all base-to-derived member variables.
- **§8.15 & §8.17 (Constructor Chaining via 'super.new')**:
  - Constructor chaining inside derived classes via explicit `super.new(...)` subroutine calls.
  - Base class constructor executes in the context of the newly created instance before derived property initialization.
  - Support for `super.<method>(...)` calling base class tasks and functions, and `super.<member>` accessing base class properties.
- **§8.20 (Virtual Methods & Dynamic Polymorphic Dispatch)**:
  - `virtual` keyword support for class functions (`virtual function ...`) and tasks (`virtual task ...`).
  - Virtual Method Table (VTable) construction during elaboration: methods marked `virtual` in base classes are dynamically inherited and can be overridden in subclasses.
  - Dynamic polymorphic dispatch: calls through base class handles (`base_ptr.method()`) dynamically resolve to the actual runtime heap object's overriding method rather than the static handle type.
  - Automatic propagation of virtualness: overriding methods in derived classes remain virtual without requiring redundant `virtual` keyword declarations.
- **§8.16 (Dynamic Downcasting via '$cast' System Task / Function)**:
  - Function form: `status = $cast(dest_handle, src_handle)` returning `1` on compatibility/success and `0` on type mismatch or null source.
  - Task form: `$cast(dest_handle, src_handle)` throwing runtime error if downcast is incompatible.
  - Dynamic type inspection against the runtime `ClassObject` inheritance tree (`is_instance_of(target_type)`).
- **2-State Data Type Default Semantics (§6.7)**:
  - Variables declared with 2-state types (`bit`) default to initial value `0` (rather than 4-state `'x'`), ensuring golden parity with commercial simulators.

## 2. IEEE Std 1800-2023 Semantics & Implementation Mechanics

### A. Inheritance Tree & Dynamic Instance-Of (`CAS/include/common/class_types.hpp`, `CAS/include/frontend/ast_module.hpp`)
- `ClassNode` records the base class relationship:
  ```cpp
  struct ClassNode : public ASTNode {
      std::string name;
      std::string base_class_name;
      ClassNode* base_class = nullptr;
      std::unordered_map<std::string, FunctionNode*> vtable_functions;
      std::unordered_map<std::string, TaskNode*> vtable_tasks;
      std::unordered_set<std::string> virtual_method_names;

      bool is_subclass_of(const std::string& target_type) const;
      bool is_method_virtual(const std::string& mname) const;
      FunctionNode* dispatch_function(const std::string& fname) const;
      TaskNode* dispatch_task(const std::string& tname) const;
  };
  ```
- `ClassObject::is_instance_of(target_type)` traverses the inheritance tree:
  ```cpp
  inline bool ClassObject::is_instance_of(const std::string& target_type) const {
      if (class_type_name == target_type) return true;
      if (class_def) return class_def->is_subclass_of(target_type);
      return false;
  }
  ```

### B. VTable Elaboration & Multi-Level Property Allocation (`CAS/src/kernel/elaborator.cpp`, `CAS/include/engine.hpp`)
- During elaboration, classes are analyzed in topological order:
  - Base class virtual method registries and dispatch tables are inherited.
  - Overriding methods in derived classes update the VTable entries.
  - Circular inheritance chains are detected and rejected.
- `Engine::allocate_class_object(class_type)` walks the class hierarchy from base-most to derived-most to allocate all constituent member properties in the `ClassObject` property map.

### C. Constructor Chaining via 'super.new' (`CAS/src/kernel/evaluator.cpp`)
- When `super.new(...)` executes inside a derived constructor:
  - Kernel extracts `current_this` from the expression evaluator.
  - Looks up the base constructor in `cl_obj->class_def->base_class->get_constructor()`.
  - Evaluates argument expressions and invokes `eval_class_method(cl_obj, base_ctor, args, dummy)`.
  - Derived member initialization continues within the same instance context.

### D. Polymorphic Method Dispatch (`CAS/src/kernel/expr_evaluator.cpp`)
- When invoking `handle.method(...)`:
  - Static type of `handle` is inspected to check if the method is declared `virtual`.
  - For virtual methods, dispatch queries the runtime object's dynamic class VTable:
    ```cpp
    if (is_virt && cl_obj->class_def) {
        fn = cl_obj->class_def->dispatch_function(method_node->method_name);
    } else if (static_def) {
        fn = static_def->find_function(method_node->method_name);
    }
    ```
  - For explicit `super.<method>()` calls, dispatch directly targets the base class implementation `cl_obj->class_def->base_class->find_function(...)`.

### E. Dynamic Downcasting '$cast' (`CAS/src/kernel/expr_evaluator.cpp`)
- `$cast(dest_handle, src_handle)`:
  - Evaluates `src_handle` to obtain the runtime object from `Engine::heap`.
  - If `src_handle == 0` (null), destination handle is set to null and `$cast` returns 1.
  - Evaluates `src_obj->is_instance_of(dest_class_type)`.
  - On success, sets destination handle to `src_handle` and returns 1.
  - On failure, leaves destination unchanged and returns 0 (or raises runtime error for task form).
