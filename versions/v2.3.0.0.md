# Release v2.3.0.0: Process Control Statements (disable fork, wait fork)

## 1. Overview & Milestone Scope
This release delivers **v2.3.0.0** of the Cycle Accurate Simulator (CAS), implementing full IEEE Std 1800-2023 compliance for:
- **§9.6.2 (disable fork)**:
  - Keyword and grammar support for `disable fork;` statements within procedural code.
  - Termination of all active background child processes and descendant threads spawned by the calling process (via `fork ... join_any` or `fork ... join_none`).
  - Caller process continuation: the calling process itself is not disabled and proceeds immediately to subsequent statements.
  - Complete cancellation of pending timer delays (`#delay`), event waits (`@(edge)`), and scheduler callbacks for all terminated threads.
- **§9.6.3 (wait fork)**:
  - Keyword and grammar support for `wait fork;` statements within procedural code.
  - Dynamic synchronization: blocks the calling parent process until all processes spawned by the current process (direct child threads and their descendants) have terminated.
  - Zero-delay pass-through: if no active descendant threads exist when `wait fork` is called, execution proceeds immediately without suspension in zero simulation time.
  - Direct Active region resumption: when the final active descendant thread terminates, the blocked parent process awakens directly into the Stratified Scheduler's Active event region.

## 2. IEEE Std 1800-2023 Semantics & Mechanics

### A. Process Control Semantics (§9.6)
- **`disable fork` (§9.6.2)**:
  - Terminates all active child processes created by the calling process through `fork ... join_any` or `fork ... join_none`.
  - Termination is recursive: any sub-threads spawned by those children (grandchildren, great-grandchildren) are also terminated.
  - The calling process is not terminated.
  - Terminated threads transition to `completed = true`, cancel any pending wait conditions (`wait_target.active = false`), clear scheduled wakeups, and are purged from parent tracking sets.
- **`wait fork` (§9.6.3)**:
  - Suspends execution of the calling process until all direct child threads and their descendants complete or terminate.
  - If the calling process has zero active descendants, `wait fork` is a no-op that finishes in zero simulation time.
  - When the last active child or descendant completes (or is disabled), the waiting parent is awakened and re-entered into the Active region.

### B. Hierarchical Thread Tracking & Ancestor Propagation
- `BoundProcess` maintains:
  - `std::vector<size_t> active_children`: PIDs of active, non-completed child threads.
  - `bool is_waiting_fork`: Flag indicating the process is suspended awaiting all descendants.
- Spawning in `invoke_fork` records each child in the caller's `active_children` vector.
- When any child thread finishes, `notify_parent_child_completed(child_pid)`:
  1. Removes the child PID from the direct parent's `active_children`.
  2. Updates and evaluates any active `ForkBarrier` (`join` / `join_any`).
  3. Walks up the ancestor process chain (`ppid -> grandparent -> ...`). If any ancestor has `is_waiting_fork == true` and `!has_active_descendants(anc_pid)`, it unblocks that ancestor and schedules it in the Active region.

## 3. Key Architectural Achievements & Refactorings

### A. Frontend Lexer & AST Grammar
- **Tokens (`lexer.hpp`, `lexer.cpp`)**:
  - Added `TOKEN_DISABLE` (`disable`) and `TOKEN_WAIT` (`wait`) to `TokenType`.
  - Implemented keyword tokenization in `Lexer::next_token()`.
- **AST Nodes (`ast_stmt.hpp`)**:
  - Added `struct DisableForkStatementNode : public StatementNode {};`.
  - Added `struct WaitForkStatementNode : public StatementNode {};`.
- **Parser (`parser_stmt.cpp`)**:
  - Implemented handlers for `disable fork;` and `wait fork;` with optional block labels and standard semicolons.

### B. Kernel Elaborator & Bound Process Model (`elaborator.hpp`)
- Extended `BoundProcess` with:
  ```cpp
  std::vector<size_t> active_children;
  bool is_waiting_fork = false;
  ```

### C. Stratified Scheduler Execution Engine (`scheduler.hpp`, `scheduler.cpp`)
- **Descendant Verification (`has_active_descendants`)**:
  - Recursively checks whether a process has any un-completed child threads or deeper descendants.
- **Recursive Thread Termination (`terminate_process_tree`)**:
  - Recursively terminates child threads and their sub-trees: marks `completed = true`, cancels `is_delayed`, `wait_target.active`, `fork_barrier.active`, and `is_waiting_fork`.
- **Disable Fork Handler (`disable_fork`)**:
  - Calls `terminate_process_tree` across all children of the calling process, clearing caller's `active_children`.
- **Process Step Integration (`step_process`)**:
  - Guarded while loops with `!bp.is_waiting_fork`.
  - Added evaluation of `DisableForkStatementNode` and `WaitForkStatementNode` across:
    * Task activation frames (`call_stack`).
    * Dynamic fork child processes (`dynamic_statements`).
    * Top-level root processes (`proc->body`).
